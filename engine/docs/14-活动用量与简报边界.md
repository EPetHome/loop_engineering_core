# 14 活动、用量、计时与简报边界（0.3.0 / u8）

## 接法与文件

本组合副本的 `adapters/pi_member.py` 是自定义 command 成员适配器，不改变内置 Pi/Codex 命令、角色授权或交付协议。原 `--model`、`--thinking`、`--tools` 参数、`--offline` 和显式权限扩展保留；新增 `--mode json`，不加 `--no-context-files`。默认仍 fresh / --no-session，不使用 continue/resume；0.3.0 集成新增显式同开发业务返修复用，精确 --session / --session-dir、实际工具 cwd 与系统旧路径保护见 [15](15-开发会话复用.md)。评审/格式修复/失败重试新会话，遥测/最终响应边界不因续接放宽。

有 `LOOP_CONTEXT` 时从其 `workspace_path`、`limits` 与单元时限取得配置；若存在该工作区的 `job/job.json`，还遵守剩余 guardian 时限、绝对 deadline 与 cancel_file。独立接法可显式传 `--workspace DIR`、`--timeout-seconds SECONDS`（只缩短原时限）；没有工作区时仍前台流式消费，但不落盘，默认硬时限 3000 秒、原始流上限 8 MiB、交付上限 1 MiB。stdio 提示与原接法相同，不经过 shell。

每个工作区属于一次成员调用，生成：

| 文件 | 内容 |
|---|---|
| pi-events.jsonl | Pi 原始 stdout 字节；逐块写入并排空，不是成员交付 |
| pi-stderr.log | Pi 原始 stderr；与 stdout 同时消费，不猜日志文字的阶段 |
| activity.json | last_event_at、last_event_type、phase、basis、按 toolCallId 的活动工具、running、finish_reason |
| usage.json | assistant_messages、tool_calls、tokens、api_requests、cost、coverage |

活动文件从首个有类型事件开始落盘，进程未退出时更新；此前缺文件表示未知，而不是无活动或卡死。终止或旧文本模式会落盘未知记录，last_event_at 可为 null。重复独立调用同一工作区会重写本适配器的文件，启动时清除上一调用的 activity，不能把它当历史存档；引擎始终给每次调用独立工作区。

`phase` 表示最后一次事件有依据的阶段：turn/agent 开始为 waiting，message_update 为 responding，工具 start/update/end 按 toolCallId 关联为 tools/waiting，重试与 compaction 为有事件依据的 waiting，缺失/异常事件为 unknown；agent_settled 且有完整交付才 completed。这是观察，不保证模型正在算、不推断 HTTP 阶段，也不把持续活动当业务进展。仅凭工具名字或 stderr 的“waiting”不能确定阶段；不匹配的工具 ID 不能关闭其他工具。

工具生命周期的任一事件都使此前交付候选失效，包括缺失/非法 toolCallId 或 update/end 未匹配 ID 的事件；关联失败显示 unknown，不能据此判定工具已完成。仅工具 end、重复 turn_end/agent_end 载荷或 agent_settled 不足以恢复旧回复。必须在这些事件之后取得新的完整合法 assistant message_end（stop）和 agent_settled，且无已知活动工具，才可交付新回复；没有这些证据时，即使子进程退出 0，适配器也非成功退出且 stdout 为空。新响应可恢复交付，但历史关联不完整的 tool_calls 用量仍为 null。

上下文压缩本身不等于开始新的业务工作。完整回复之后发生压缩时暂留该回复、取消已完成标记；仅开始/结束原因匹配，结果字段有效，aborted=false、willRetry=false 且无错误时，才允许在后续 agent_settled 和成功退出后交付。压缩期间的摘要生成重试属于同一次维护；压缩失败、中止、未结束、状态不明，或出现新用户/助手/工具/队列工作、业务重试时，旧回复仍不可交付。此规则也适用于使用同一解析器的辅助简报。

## 用量：已观察不等于完整计量

- 只累计 assistant 的 `message_end.message.usage`。message_update 的累计快照、turn_end / agent_end 的重复消息不再累加。assistant_messages 是已观察最终消息数，tool_calls 是 execution_start 的唯一 toolCallId 数（关联不完整则未知）。
- tokens 四维为 input、output、cache_read、cache_write。某维任一已观察消息缺字段/无合法数值，该维汇总为 null；coverage 分维给 known_messages / observed_messages 和 observed_total。provider 明确报告的 0 是已知 token 数，缺失不是 0；小计不能冒充总数。
- api_requests 始终为 null：模型轮次、retry 事件、成员调用数均不足以证明完整底层 HTTP 次数。
- cost 始终为 null：订阅账号实际计费与 provider 价格未验证；包括 provider cost=0，也不能称“实际免费”。compaction/branch-summary 以及隐藏请求用量未纳入 assistant 汇总，coverage 明示范围；重复理解成本没有计量。
- 旧文本程序仅在从未出现 JSONL 类型事件且成功退出时兼容解析，所有事件/用量维度未知。已进入事件模式后，不允许用旧轮回复、delta 半段或文本回退补交付。

## 输出、取消与计时

JSONL 只按 LF 切帧，兼容 CRLF；拆包/UTF-8 和 JSON 字符串内 U+2028/U+2029 不产生新记录。单行缓冲不得超过 limits.max_log_bytes；原始 stdout + stderr 累计字节共用该上限，文件只保留限内前缀，超限立即停止且不交付。总限制不是整个运行的磁盘/内存配额；最终 JSON 和少量适配器诊断还受原 guardian 输出上限约束。

stdout 只输出最后完整 assistant 文本中的 JSON 对象，且必须 message_end.stopReason=stop、agent_settled、无未完成工具/后续工作、流合法及进程成功退出。取消、硬超时、超量、非零退出、无最终合法响应都不交付半段或上一轮 JSON。活动不会重置硬超时。适配器不创建新进程组；引擎原 guardian 负责整组清理，独立调用负责直接子进程，不是抵御故意脱组的沙箱。

本适配器的内部事件写入工作区，尚未作为 guardian 的无输出计时信号；`idle_output_seconds` 应保持默认 0。非零值可能在 Pi 持续输出内部事件时提前终止任务。阶段/总时限、取消和日志上限仍然有效；本次兼容修复没有引入心跳或延长硬时限。

每份 runner receipt 保留原 elapsed_seconds（monotonic），新增同一个 guardian 命令范围的 wall_elapsed_seconds（epoch 墙钟差）、timing_difference_seconds、timing_discrepancy 和 timing_note。范围含启动、执行、管道排空与清理；绝对差 > 2 秒会标志并说明，不直接归因模型。合成时钟反例只验证标志逻辑，不证明实际差异成因。引擎 result.elapsed_seconds 仍为运行创建到收尾的端到端墙钟，包含门禁、I/O、等待和调度；并发成员时间之和不是该总时间。

## 引擎状态与可选简报

引擎心跳读取工作区的有界 activity/usage；缺失、损坏、超大或链接投影记为未知并保留读取错误，不由遥测决定标准通过。`units.<ID>.member_activity` 提供最近观察；member_observations 按 attempt_id 保存各次活动、用量、回执（含失败/格式/基础设施重试）。member_usage 分维汇总，任何缺失调用/维度使总值 null，coverage 的 observed_total 仅是有计量调用的小计；member_processes 独立汇总 guardian 计时。终态同时进入单元/总结果，原文件封存并纳入 audit。member_invocations 仍是原成员启动预算计数，未改为 assistant 消息或 API 数。

`loop.py status` 文本显示成员阶段、last_event、basis、工具 ID 与用量；`status --json` 给完整记录。无新 CLI 调度/监控命令，无观察员模型。旧记录缺遥测时仍可读取，显示未知，不补造数据。

组合入口 `run_loop.py PLAN --root DIR` 保留启动方式与原 supervise 退出码，默认完整终态后只生成 `交付结果.md` 与 `delivery-overview.json` 并打印结果位置；状态说明「未请求 AI 简报」。无论日志长短都不启动辅助模型、不等待模型、不扫描全部日志判断长度，旧长度阈值已删除。

仅显式追加 `--brief` 才在完整终态且未取消时为精确本次运行调用一次辅助简报，短日志也尊重请求。原始结果先写出；原简报型号 opencode-go/deepseek-v4.1-flash / xhigh、只读工具、权限扩展、300 秒时限与独立计量不变，失败、空响应、超时、取消降级到原始结果，不重启开发。提示词随交付的 `prompts/brief.md` 提供，不依赖私有绝对提示词文件；简报仍使用同一 JSONL 投影器且明确 --no-session。`brief-job/` 保留原命令、回执、原始事件、活动与用量，stdout.log 仅完整简报正文；旧离线文本简报桩仍兼容。

`delivery-overview.json` 和 `交付结果.md` 分开列引擎预算调用数、端到端耗时、成员可用用量，以及额外简报启动尝试数、两类计时和可用用量。它们是辅助视图，不把简报加入原 manifest 的成员预算/结果，不改原终态；入口仅链接存在的对应结果文件。简报计数按本运行累计，含已有历史记录，不表示当前交付新增调用；默认重新生成视图不会调用模型或把历史简报记成新启动。

简报提示明确区分本次真实成员是否参与（不能由进程计数或假桩通过推导）、新增接法真实验证未进行、人工验收 NOT_PERFORMED；链接须核实对应目标。静态提示与入口检查不保证真实模型生成的每句话正确。

## 验证范围

新增离线回归在原 engine/tests 与组合 tests 中，由冻结 REG 发现；覆盖 A 型源变化/收尾与 B 型返修/证据绑定同时使用 JSONL 接法，保留原授权、取消、假成员和禁用真实模型边界。覆盖拆包/UTF-8/Unicode 分隔符、多消息、重复载荷、重试/compaction、字段缺失、工具 ID、大 stderr、单行/总流/响应上限、失败退出、取消、硬超时与计时差异。C3 返修另增 8 项反例：已 settled 回复后出现缺失/非法/未匹配 ID 的工具事件，旧载荷或再次 settled 不能放行；无新合法完成响应时非成功退出且 stdout 为空；正常工具关联与后续完整新响应仍可交付。

本单元只验证本地协议桩、静态文案和合成时钟；真实 Pi/Codex CLI、账号、模型质量、真实 HTTP 次数、实际费用、会话复用与时间/成本节省、人工业务验收均未验证。0.3.0 集成已统一版本和 SHA256SUMS，0.2.0 / 0.1.0 历史正文未改；真实会话收益仍须由用户另行对照，不能用离线桩或新版本号补认。
