# 10 安全边界与已知限制

## 1. 不把轻量防误改叫安全沙箱

源码副本、只读文件、路径检查、SHA-256、角色协议，能减少误写并阻断部分不合规结果。它们不能阻止具有同等用户权限的进程访问别处。Pi 和任意 command adapter 的工具在同一操作系统账号下运行，可能读 HOME、访问网络、改其他路径。

“原项目不被覆盖”指**引擎本身**从不向原项目回写。未经系统隔离的成员若恶意绕开给定 cwd，仍有本机账户权限。**原项目被成员改动：能发现、不能阻止。** 正常收尾时，按启动时的范围和排除规则重新扫描本次输入来源，与输入快照清单比较；差异写入总结果的 `source_drift`，总停止类型为 `BLOCKED`，但不改写单元结论，也不自动还原原项目。扫描失败会记录 `source_drift_error` 并以 `BLOCKED` 收尾；故障恢复补写结果不做这次核对。排除路径、扫描前已还原的短暂改动不在检测保证内；retry 核对的是所复用的输入快照目录，不是另行追踪原项目。不要给此版未审查的项目指令、未知 wrapper、不可信扩展、生产数据或生产写凭据。

单元 `reviewer_exec=true` 允许评审方执行只读的取证命令并写自己的取证目录。这里的「只读」靠角色约定加事后核对，不是沙箱：bash/write 或自定义工具并没有被 OS 限制为只能写取证目录。提示禁止修改候选副本、门禁证据、规则、交接记录和原始项目；程序仍在评审后比较候选指纹、核对冻结记录并做原项目收尾核对，发现改动仍 BLOCKED。取证目录位于候选之外；只对已接受交付引用的文件设为只读并记录 SHA-256，`audit` 能发现它们事后被改，不验证命令的业务正确性或未引用文件。

取证目录普通文件累计大小上限沿用 `limits.max_log_bytes`，在交付验证时检查，包含未引用文件；这不是实时磁盘配额。格式错误重交保留并复制取证内容，未引用文件不自动删除。内置 Pi 开关打开时增加 bash/write；内置 Codex 仍是 read-only 沙箱，取证目录不可写，不自动扩大权限。自定义 command 必须自行配工具。

生产风险任务需要另行使用独立账号/容器/受控沙箱、网络出站策略和明确权限。本包不擅自装这些，也不声称已提供。

### 显式会话复用的额外系统路径保护

0.3.0 默认 fresh 的上述边界不变。仅交付内本地 Pi command/stdout 开启 developer_session=reuse_repairs 时，每次先实质探测 macOS sandbox-exec，再把 Pi 及 bash/Python 后代置于 Seatbelt，禁止本数据根旧 checkouts、artifacts、snapshots 及本单元其他会话文件写入（当前 code_path / 选中会话文件是相应例外）。旧绝对路径、符号链接别名、chmod 改权限绕行实际拒绝；当前业务开发目录仍可写，评审/格式修复只读不因此放宽。平台/权限不支持明确拒绝，没有 chmod/提示替代保护。

这是有限的旧数据路径 OS 写保护，不是全机器、原项目、网络、账号或恶意脱组隔离。不改全局 Pi/权限插件/凭据，不给新外部动作权限。自有 session header 持文件锁仅改 cwd、保留历史和 id，映射锁/归属检查阻止跨运行/单元/角色/规则/输入/配置继承；不会修改用户会话。具体契约与失败路径见 [15](15-开发会话复用.md)。

## 2. 路径与快照范围

包含的符号链接和特殊文件会拒绝。被排除的依赖、缓存、.env 不跟随、不复制，也不作为候选指纹的一部分；不能因此把“没有检测变化”理解成这些路径从未有任何活动。

默认排除不是秘密识别。私钥、自定义 credentials.json、证书等可能仍在普通源码树内，请由拍板人使用 exclude_paths 明确排除。排除掉的必要业务材料也不会给模型或导出结果，不能误用。

全过程使用完整副本，会增加磁盘占用。max_source_bytes 是每棵树限制，不是整个运行根目录上限；成员仍可能写大量未纳入扫描的缓存或超大文件直至进程停止。没有磁盘配额、内存配额或容器限制。

comparison 明确授权只读其索引中的本运行本单元冻结输入、上轮候选旧正文和完整差异，不授权读取原项目、其它单元或其它运行。程序在交接时核对快照身份，差异文件只读封存；这仍不是同账号强隔离。完整差异和原报告可能包含纳入快照的敏感正文，分享前人工检查，不能用静默删规则/差异来掩盖超预算。问题显式解决只能证明声明及证据绑定当前候选、关联门禁有效，不保证评审业务判断正确；原始提出和旧解决保留，不能把未再提及当解决。

## 3. 原始日志与凭据

成员环境按显式名单继承，但 HOME 与代理配置会保留，CLI 可访问原本的账号文件。门禁使用单独 HOME、不传成员 opt-in 密钥，却仍然是同系统账号，不能阻止主动读取其他位置。

argv/job/原始 stdout/stderr 可能含成员或第三方工具打印的敏感信息。程序不读取并打印凭据来做 doctor，但**不承诺日志自动脱敏**。禁止把密钥放 argv/notes/规则或上传公开渠道。分享运行记录前人工检查。

## 4. 有界不等于精确计费

成员进程调用数量、阶段时间、总时间、输出和上下文有上限；一次成员进程可能包含多次 API 调用、工具调用、隐藏重试或不同供应商计费。组合 Pi JSONL 接法仅按 message_end 分维给 token_usage / member_usage；任何缺测维度为 null（全部缺测时旧 token_usage 仍为 null），coverage 明示小计与排除的摘要/隐藏用量。api_requests、实际 cost、重复理解成本仍未知，provider cost=0 不证明免费，没有精确美元预算保证。活动不延长硬超时，原始双流与单行缓冲同受 max_log_bytes 限制；这不是整个运行的系统配额。账户层限制仍由用户和供应商管理；详见 [14](14-活动用量与简报边界.md)。

程序不做会话保温，不会定时触发额外模型调用。通知、状态读取、收尾和恢复不需要模型。

## 5. 进程与外部副作用

只管理本次进程组。禁止成员启动 setsid/detached 服务、远端后台任务、推送/部署、生产写接口等。受管进程被杀不代表已经发送的网络动作能撤销；本版没有通用 exactly-once、远端查询与补偿能力。

两个独立运行的 resources 名称不形成跨运行锁。需要共享数据库/端口/账号的多个运行应由用户分配独立资源，不靠 task_id 自动去重。

## 6. 可恢复性的真实边界

当持久存储可用、权威记录可读时，监督故障可自动或通过 recover 补齐结果。机器断电、磁盘故障、记录全部丢失，不能当场保存不存在的结果。没有自动备份、异地复制、开机自启。

写到一半的权威记录用原子替换保护；但这不能覆盖硬件损坏或恶意改写整份清单。指纹在交接与审计时检查，不是全时文件追踪。

总收尾 `finalization` 和总体结果在同一权威记录中提交。正常核对异常为 FAIL；若总提交未落盘，即使单元全部 PASSED，恢复也只能给总收尾 UNKNOWN、总体 BLOCKED，保留单元成果而不猜测成功。正式导出同时验证完整性和总收尾有效 PASS；旧记录缺少总收尾证明不会自动补认。总收尾 PASS 是当次扫描的结论，不能保证提交后原项目永不变化，导出也不会偷偷改旧结论或重新验收业务。

## 7. 测试与模型结论

程序验证证据属于当前候选、是否完整，不证明所有语义判断正确。开发和评审可共享模型盲区。测试命令退出 0 不能自动证明用例数量正确或标准没有遗漏。新场景应加入真实行为门禁，不要无限增加互相投票的模型。

旧构建期验证见保留的测试报告；本次 macOS 仅做离线进程及系统路径拒写验证，未连接真实 Pi/Codex，没有 macOS/WSL 生产认证，没有完成用户 Promax 业务验收。用户最终验收不可省略。

迭代03新增验证限于离线成员报告、收尾故障、版本比较/问题证据、流式用量、会话归属/锁/回退及实际旧路径拒写反例；不运行真实 CLI 成员、账号或生产服务。真实模型质量、CLI/账号适配、会话复用的成本或时间节省均未验证；默认新会话保持不变，不能把离线协议桩当作真实收益达标。

## 8. 清理与升级

没有自动清理命令，避免删掉证据。需要清理时先确认运行已终态、没有活跃进程、必要成果和证据已经归档；只删除你明确识别的数据目录，不使用模糊路径或广泛进程清理命令。

冻结文件可能只读，需要你按本机文件管理方式处理权限。引擎不会自动 chmod 清空用户目录。升级引擎前停止任务，并保留旧版本及其记录；运行期间代码变化会触发自检故障。
