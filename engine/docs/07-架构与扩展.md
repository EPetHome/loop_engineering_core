# 07 架构与扩展

## 1. 最小业务骨架

```text
冻结规则/输入 → 开发 → 交付协议校验 → 冻结候选
                              ↓
                   程序门禁 → 独立评审 → 全部有效通过？
                                             ├ 是：达标交结果
                                             └ 否：有业务返修预算？
                                                    ├ 是：开发返修（默认新会话；可显式同开发续接）
                                                    └ 否：未达标交结果
故障、越界、失去执行者 → 推不动交结果
```

DAG 在单元外看依赖，不在单元内部加入经理/观察员。线程只负责并发编排；成员与门禁始终是独立受管子进程。

## 2. 模块职责

| 模块 | 作用 |
|---|---|
| loop.py / cli.py | 命令入口、环境检查、创建运行、查询与导出 |
| rules.py | 严格规则规范化、DAG、边界冲突、Markdown 视图 |
| common.py | 严格 JSON、原子写、POSIX 锁、快照/指纹、路径与环境处理 |
| storage.py | 权威清单、计数、封存记录、结果视图、通知 |
| protocol.py | 成员 JSON schema、交付验证、可选显式解决声明、门禁覆盖语义结论 |
| handoff.py | 只读输入/上轮比较与完整 diff 索引、稳定问题 ID、原始来源和当前状态投影 |
| adapters.py | Pi/Codex/自定义命令，当前权威身份提示及上下文 |
| sessions.py / session_sandbox.py | 自有 Pi 会话明确映射、配置/归属/两层锁、header 工具 cwd 重绑与 macOS 旧路径写保护；默认关闭 |
| engine.py | 单元循环、候选冻结、独立门禁、DAG组合与停止 |
| runner.py | 每命令 guardian、输出采集、时限、父进程丢失与进程组清理；同范围 monotonic / wall 回执 |
| pi_events.py / observability.py | 有界 Pi JSONL 活动与 message_end 用量投影、最终响应筛选、有覆盖范围的成员汇总，不调用模型 |
| supervisor.py | worker 监督、孤儿恢复、信号处理 |
| audit.py | 存档完整性与总收尾绑定核对、只向新目录导出 |

## 3. 数据布局

```text
ROOT/runs/RUN/
├── rules.json / rules.md          权威规则快照和自动阅读版
├── response.schema.json          完整交付协议
├── manifest.json                 唯一权威状态与结果
├── events.jsonl                  程序事件
├── supervisor.lock / owner.lock  单一拥有者锁，锁文件不随意删除
├── controller.log                控制进程原始日志
├── units/UNIT/
│   ├── input.json                当前单元组合输入身份
│   ├── candidate-001.json         当前/历史候选清单、差异
│   ├── sessions/                 opt-in 的 developer.json 映射、UUID 会话/owner 和不删除的锁
│   ├── attempts/ATTEMPT/
│   │   ├── context.json           本次有效上下文（comparison / issue_history）
│   │   ├── comparison.diff        完整只读差异（context 给路径、指纹与大小）
│   │   ├── response.template.json 本次生成骨架，默认全 UNKNOWN
│   │   ├── session-choice.json / session-protection.json  会话选择与实际保护探针（后者仅 opt-in）
│   │   ├── pi-events.jsonl / pi-stderr.log  组合 Pi 接法原始双流
│   │   ├── activity.json / usage.json       进程未退出即可更新的有界投影
│   │   ├── response.json          成员交付
│   │   ├── accepted.json          程序核对后包上身份的交接
│   │   └── job/                   命令、stdin、日志、进程身份、回执
│   ├── gates/r001-G1/             本次候选的程序测试证据
│   └── result.json                单元结果阅读视图
└── result.md / result.json / report.html / notification.json

ROOT/snapshots/RUN/                源快照、单元输入、格式修复冻结种子
ROOT/checkouts/RUN/UNIT/            可执行但不自动回写原项目的副本
ROOT/artifacts/RUN/UNIT/round-NNN/  历史和当前候选代码
```

工作区保存规则、交接和记录；产品代码分别放 checkouts 和 artifacts，符合原稿“产品文件不混入交接文档”的区分。完整拷贝而非 worktree 使无 Git 项目也能用，代价是磁盘和复制开销。

## 4. 状态与事务

运行：CREATED → RUNNING → TERMINAL。单元：PENDING → RUNNING → TERMINAL；phase 进一步显示 preparing/developing/testing/reviewing/finalizing 等细节。终态结果与状态在一次 manifest 原子替换中一起提交，不存在“状态成功但本次结果未写入”的正常窗口。

单元全终态后，Controller 复用完整性审计核对冻结证据、输入快照及全部当前候选，并按启动范围扫描本次原项目来源。核对结果只在内存中计算，由 Store.finish_run 把 `result.finalization` 的状态、规则/输入/当前候选绑定与总体停止类型一次原子提交。只有两项核对已完成且无异常才 PASS；异常为 FAIL，未执行或无法确认完成为 UNKNOWN，后两者都总体 BLOCKED，不改各单元成果。缺少完成标志的 finish_run（如孤儿恢复）不会从空差异数组推断通过。已终态只重建视图，不补做核对。

写法：同目录临时文件、fsync、os.replace，再尽力 fsync 父目录。进程异常退出后可以用已提交记录恢复；这不是抵御磁盘硬件丢失的复制数据库。

关键交接文件设只读并记 SHA-256。成员不能通过少填标准、重复 ID、旧 attempt_id、旧候选哈希或范围外建议绕过检查。评审意见里的新标准不计入本轮门槛。

## 5. 上下文不是整段历史回灌

每次成员调用（包括显式业务续接）收到：适用单元规则、实际标准内容、任务 notes、输入/候选身份、工作副本、必要反馈、当前门禁证据、comparison、issue_history、协议与模板。comparison 指向本运行本单元的冻结输入、上轮候选与完整只读 diff，给相对输入/上轮的变化路径及上轮已接受评审原报告。开发看到当前起点、评审看到当前候选；旧正文直接可读，不从当前文件复原，不扩大旧材料读取授权。开发方不需要拿到评审启动命令。旧日志不全部塞入提示。

issues / rule_gaps 的来源不可变，历次提出与处理只追加；状态是当前候选投影。仅评审可显式解决已知 ID，证据及门禁绑定当前候选，未提及/标准 PASS 不自动关项。已接受交接的 ledger 和轮次 history 写入原有权威单元状态，收尾/恢复保留记录，但不猜测通过。result.rule_gaps 区分当前未解决与全部历史；旧终态只读兼容、不补造历史。字段见 [13](13-版本比较与问题历史.md)。

组合 Pi 适配器持续消费 JSONL 双流，在原工作区记录活动和最终消息用量；engine 心跳读取到原 manifest 的 member_observations / member_usage，缺测为 null，失败/重试调用仍保留，终态封存投影。没有增加平台或独立观察进程；原 member_invocations 仍是启动预算计数。可选简报由 run_loop 使用同一投影器，额外计量在独立辅助视图，不改原终态。范围详见 [14](14-活动用量与简报边界.md)。

会话默认 fresh。显式本地 Pi reuse_repairs 使用按 run/unit/role/rules/input/开发配置绑定的映射；在已有单元目录维护明确 UUID 路径与选择原因，映射锁覆盖交付验收，文件锁覆盖 header.cwd 原子重绑及 Pi 调用。macOS Seatbelt 保护旧 checkouts 和冻结树、继承给 bash/Python，能力不足拒绝启用；损坏/缺失/归属不符不猜测，安全时新建 fresh。评审/格式修复永远新会话，旧回执严格拒收，作用与真实验证边界见 [15](15-开发会话复用.md)。

状态/事件的持续写入由程序完成，不每轮额外调用模型维护记忆。完整 diff 在封存文件中给索引，未裁掉差异；上下文超限会明确停止，而不是把关键规则、原评审或问题历史裁掉。没有智能摘要服务；保持小型、可独立验收任务。

## 6. 扩展顺序

适配新工具优先写外部 command wrapper，不先改核心状态机。修改规则字段需同步 normalize、阅读版、上下文、测试与手册，不能只加一个被程序忽略的键。

增加外部副作用前需要确定：授权边界、幂等键、远端操作可查询状态、取消/补偿和断网后的未知处理。当前版禁止生产/不可逆操作，不提供这些协议。

增加并行能力前先验证单元正确、无共享隐式写入、合并规则与集成门禁。资源字符串只在本次 DAG 内互斥，不能当分布式锁。

修改后运行 selftest。运行期间引擎会核对自身代码，因此不能一边修改源码、一边用同一份引擎跑任务。测试中的协议桩和故障注入不是独立模型评审，也不是生产完成证明。
