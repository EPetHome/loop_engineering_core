# 01 快速开始

## 1. 放在哪里

解压 `Loop-Engineering-0.1.0.zip`。终端进入包的根目录，即包含 `loop.py` 的目录。例如你放在桌面时：

```bash
cd "$HOME/Desktop/Loop-Engineering-0.1.0"
python3 --version
python3 loop.py doctor
```

示例路径只表示常见放法；以你实际解压位置为准。Python 要求 3.10+。引擎没有第三方 Python 依赖，不需要安装数据库、服务端或 Node；只有真实成员 CLI 自己可能需要额外运行环境。

Linux 是本次已验证环境。macOS、WSL 使用 POSIX 路径，需本机试跑；原生 Windows 不受支持。终端提示找不到 `python3` 时，需要先按你电脑的管理方式安装 Python。不要因此用系统管理员权限启动真实成员。

## 2. 无账号、无模型的第一次试跑

```bash
python3 loop.py demo
```

这是**离线成员协议桩**：开发方是一个可预测的小程序，评审方也是单独启动的小程序。它们不是 AI，但是引擎真的执行以下步骤：

```text
读取示例输入 → 独立副本里第一次修改 → 真实单元测试失败
→ 独立评审 → 自动安排一次返修 → 第二次修改
→ 真实单元测试通过 → 独立评审 → 达标结果
```

预期：邀请重发只对 `pending` 且 `expired=True` 生效；最终达标，业务返修 1 次、成员调用 4 次。原文件 `examples/demo_project/invites.py` 保持最初有缺陷的示例，不被覆盖；修复版在候选成果中。

这证明程序的流程能工作，不证明真实模型一定能完成任务。

## 3. 看结果

```bash
python3 loop.py status
python3 loop.py result
python3 loop.py audit
```

启动输出中有三个信息：运行编号、Markdown 结果路径、HTML 报告路径。HTML 可直接在浏览器打开，完全本地、不需服务器。`audit` 应返回 `"integrity_ok": true`，它核对存档指纹，不重新推理业务。

默认数据根目录是**运行命令时当前目录**中的 `loop-data`。换终端目录后，必须使用同一个 `--root`。正式任务推荐固定绝对路径，并记录运行编号，不只依赖 latest。

## 4. 导出修复后的代码

在只跑完单单元 demo 的情况下：

```bash
python3 loop.py export --to ./demo-output
```

`demo-output` 必须不存在。输出是候选的完整纳入范围快照，不是差异补丁；排除的 `.git`、依赖目录和秘密文件不会出现。命令不会将任何文件写回原项目。

如果已经跑了其他任务，上述默认选择的是最近创建的运行。用显式编号避免混淆：

```bash
python3 loop.py export 这里替换为真实运行编号 --to ./another-output
```

这里的中文占位符不是可直接执行的真实编号，请复制终端打印的值。

## 5. 并行和集成演示

```bash
python3 loop.py demo --dag
python3 loop.py status
python3 loop.py result
```

前端与后端两个单元并行，各自达标后，集成单元读取两者确定版本的组合成果并验证接口相容性。总计三个单元，预期全部达标。

## 6. 下一步接真实工具

阅读 `04-成员工具接入.md`。包内已有 `examples/real_pi_codex.json`：同一个小型邀请任务，改为 Pi 开发、Codex 独立评审。先确认本机 CLI 已安装、登录、可用，再由用户启动。真实调用不属于离线演示，可能消耗订阅额度或 API 费用。
