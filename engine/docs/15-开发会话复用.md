# 15 显式开发会话复用（0.3.0）

默认 `units[].developer_session="fresh"`，只接受 `fresh` / `reuse_repairs` 两个字符串。省略字段等同 fresh；布尔值、null、continue、空串等拒绝。

## 接法与生效范围

复用只支持本组合交付内 `adapters/pi_member.py` 的 **command / stdout** 接法：argv 直接执行这个绝对路径脚本，或 `python` / `{python}` 加这个绝对路径（也支持 `{engine}/../adapters/pi_member.py`）。型号、思考级别、工具及显式权限扩展约定不变。任意 shell/wrapper、内置 pi、codex、command/file 不支持，规则预检明确拒绝，不把新进程伪装成复用。默认 fresh 下原接法仍可用。

```json
{
  "kind": "command", "identity": "approved-developer",
  "argv": ["{python}", "/absolute/composed-project/adapters/pi_member.py",
           "--model", "已确认可用的provider/model", "--thinking", "max",
           "--tools", "read,bash,edit,write,grep,find,ls"],
  "output": "stdout", "inherit_env": ["LOOP_PI_BIN"]
}
```

这是 agent 片段，不是完整任务；其他角色、范围、标准、门禁与预算仍由拍板人确认。**本次开发没有启动这条真实调用。** `--offline` 只禁 Pi 自动联网，不禁用户启动后的模型请求，不能当“不计费”。

首轮是新建引擎自有持久会话；仅同 run / unit / developer 配置下，上一业务轮已接受且可用的会话才能在下一业务返修轮复用。每次仍独立新进程、attempt、工作区、code_path、候选和门禁。评审始终 fresh / `--no-session`。格式修复使用独立新会话、冻结代码，不能续接原会话，也不作为下一业务轮复用的种子。基础设施失败只重试新会话；失败会话留存但不再选中。新 run、retry、其他单元/角色、规则/输入或配置不继承会话和旧 PASS。

## 映射、锁与实际工具 cwd

`runs/RUN/units/UNIT/sessions/developer.json` 是程序维护的明确映射：binding 包含 run_id、unit_id、role、rule_hash、unit_input_hash、developer_config_hash（规范化 agent 与有效继承环境的摘要，不保存密钥值）；记录 session_id、精确 session_path、owner_path、当前 attempt/code_path/round、ready 和原因。ready 必须为 JSON 布尔值，只有字面量 true 允许复用；false 沿用未接受/不可复用原因，缺字段或非布尔值（包括字符串 "false"、数字 1）记录 `fallback_fresh: corrupt session mapping: ready must be a boolean` 并新建 fresh，不能用真值转换猜测资格。此校验在重写当前 attempt 映射之前执行，原会话不改。每个会话有 UUID 命名的 `.jsonl` 与只读 `.owner.json`；不会搜索用户会话目录、partial ID、latest 或 continue。映射不是标准通过的证据。

选择到交付校验期间持 mapping.lock，适配器另持每个会话的 `.lock`，覆盖归属核对、header 变更及 Pi 前台调用；非阻塞锁竞争直接拒绝，不分叉覆盖活跃会话。锁 inode 不删除，检查普通文件、uid、单硬链接与各层符号链接。每次 `context.session` 及封存的 `session-choice.json` 给 policy、mode、显式 session_path（fresh 对照/评审为 null）、previous_code_paths、binding、previous_cwd 与选择/回退原因。

接法依据为组合交付的 `reference/pi-cli.md`、`pi-sessions.md`、`pi-session-format.md` 和本机 **Pi 0.87.1 已安装源码的只读摘录 `pi-local-cwd-source.txt`**：

- `--name` 仅显示名称，不能新建/选择会话身份。程序先创建合法 v3 header，再使用 `--session <精确绝对文件路径> --session-dir <本单元自有目录>` 打开它；首轮也如此。fresh 对照及评审使用 `--no-session`。没有 `--continue`、`--resume` 或用户既有 session。
- 摘录 main.js:264/308 打开指定文件调用 `SessionManager.open(path, sessionDir)`，不传 cwdOverride；session-manager.js:1326–1347 默认读 header.cwd；main.js:681–684 用 `sessionManager.getCwd()` 创建实际 runtime/tools。**只传子进程 cwd 不够。**
- 选择、交付后可用性检查及适配器重绑前共用同一 v3 校验：除映射/owner/header/id/历史树外，验证已知条目的必需载荷、entry 的 ISO timestamp、message 的数值 timestamp、角色对应 content/块/用量/工具与 system patch 结构，以及 compaction/context_edit/label 等引用。`message=null`、缺失或非对象 message、非法内容块等即使是合法 JSON 也不可续接。未知 entry type / message role / 内容块不猜扩展 schema，明确回退 fresh；任意 custom data/details、未知 usage kind 及额外元数据仍保留。
- 适配器持文件锁，在上述校验通过后，原子替换自有 header 的 **cwd 单字段**，保留其余 header 字段和所有历史 entry 的原始字节/id；重新检查后才启动 Pi。仅修改本运行自行创建的会话，不改安装源码、用户会话、全局 Pi 配置、权限插件或凭据。离线桩读取重开 header 后的 cwd 去写当前文件，验证不是仅变 name/子进程 cwd。真实 CLI 实接仍未验证。

续接提示最前面重申本次唯一权威 code_path、attempt 和 candidate_hash，历史目录只能只读比较。旧 attempt / candidate 回执仍走原协议拒收；复用不跳过任何证据、门禁或独立评审。

## 旧路径保护与失败策略

启用策略必须在 macOS 有可执行的 `/usr/bin/sandbox-exec`。每次调用先运行短时、同进程组的能力探针：bash 启动 Python，写旧绝对路径和其符号链接别名必须被 OS 拒绝，当前开发目录必须可写。失败或不支持平台直接非成功，不能退成“有保护”的普通 Pi。

实际 Pi 命令置于同样 Seatbelt profile，后续 bash/Python 子进程继承：deny file-write* 覆盖本数据根的 checkouts（仅排除权威当前 code_path）、artifacts、snapshots 和本单元 sessions（仅允许当前选中的会话文件）；保护目录祖先不能被改名删除。旧目录仍能只读比较；旧目录/候选写入包括 chmod、绝对路径与符号链接别名实质拒绝。`session-protection.json` 保存探针结果、范围及 profile，完成后封存。评审/格式修复当前代码本来只读，探针写工作区，不宣称这些阶段代码可写。

这不是全机器、原项目、网络、账号、磁盘配额或恶意逃逸的隔离证明；不提升原权限。fresh 不开启这项 OS 保护。真实本机权限扩展仍可能拒绝合法工具，用户不得为跑通擅自关闭它。

映射损坏/失踪、binding 不同、会话丢失/损坏、header cwd 或 owner 不符、非连续业务轮、格式修复/失败未接受时，都不猜测续接：在自有目录分配新的 UUID 会话、记录明确 fallback_fresh / 原因，原会话不覆盖。损坏载荷选择时记录 `fallback_fresh: corrupt session: ...` 并新建文件；选择后到重绑前若再损坏，适配器拒绝给出 CLI 会话参数，不改旧 header 或历史；交付后发现损坏则 ready=false，下一轮不得继承。已封存的 owner 归属证据若被改，原完整性核对也可在选择前直接 BLOCKED；不忽略篡改。路径/锁 namespace 不安全、竞争或 OS 保护不可用时拒绝调用。新会话也仍需同样保护；若失败则沿用原 infra 重试及 BLOCKED 收尾，不重复接受旧交付。会话文件上限 32 MiB，超过按不可用处理，不静默裁历史。

## 对照与验证范围

本单元增加离线归属、跨 run/unit/role/rules/input/config、锁竞争、坏/缺/链接会话、格式修复、新进程失败、旧回执与实际旧路径拒写反例；第二轮补充合法 JSON 但载荷损坏（含评审的 message=null 原例）、选择后再损坏、交付后损坏及完整有效 v3 载荷/字节保留的反例与正例；第三轮补充从格式修复 ready=false 映射出发的 9 种非布尔/缺字段损坏，核对新建 fresh 的映射/事件原因、旧 header.cwd/历史/owner 字节不变，并保留布尔 true 连续返修正例；组合测试串起两轮业务返修、当前问题显式解决、活动/用量、三轮候选与真实门禁、总收尾 PASS 和正式导出，不只检查假成员自报。

真实任务的同模型/同标准/同预算 fresh 对照与 reuse 启动步骤在组合项目 [本机验证与会话对照](../../docs/本机验证与会话对照.md)。本次只做离线检查及开发静态自检：**真实 CLI、账号、模型质量、真实会话收益/节省比例及人工验收未验证。** 外层当前任务仍由旧引擎/旧接法驱动，新实现没有部署生效。用户另行启动与验收决定合并，交付不会自动合并、导出生产或更新基线。
