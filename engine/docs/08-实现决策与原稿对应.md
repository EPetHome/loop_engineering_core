# 08 实现决策与原稿对应

本文件记录本次开发选择，不把上一轮建议追认成用户此前逐条签字的历史决策。九份原稿原样保留；前次审查补充也单独保存。本次用户授权制作程序后，采用以下保守实现以交付可用首版。

## 1. 保留的核心

| 原稿原则 | 本版落地 |
|---|---|
| 用户只启动与验收 | 静态规则 + run/start；无中途人审状态 |
| 开发和评审不同方 | 分别配置 identity、分开进程；默认 fresh，仅显式同开发业务返修可续接，评审/格式修复新会话 |
| 单元小骨架 | 开发—门禁—评审—返修/停止 |
| 标准逐条可检 | 完整 ID 校验、PASS/FAIL/UNKNOWN、必需门禁 |
| 停止即交结果 | 原子权威清单；监督/guardian；故障降级结果 |
| 规则不可由成员修改 | 只读快照、封存指纹、交接与最后核对 |
| 每单元工作区 | units/UNIT 独立交接，产品代码独立目录 |
| 不碰基线 | 原目录不由引擎改写，不自动合并、提交、发布或更新基线 |
| 并行和串行 | 静态 DAG、依赖失败跳过、无关单元继续 |
| 不用模型守望 | 进程、时限、事件、通知全部用程序 |

## 2. 本次新落地选择

**Python 标准库 + POSIX 进程。** 便于直接在本地运行，无数据库/依赖安装；代价是原生 Windows 暂不支持，macOS/WSL 仍需本机验收。

**复制快照，不用 Git worktree。** 源项目不必使用 Git，用户未提交文件也可以成为固定起点。代价是依赖环境不自动复制，磁盘使用更大。

**三层程序监督，而非模型 Sidecar。** 单次 worker 故障可自动收尾；主机或两个控制进程都退出时，需要用户下次 recover。没有系统服务/开机自启。

**规则语义仍由拍板人确认。** 结构预检必做，不能用程序声称发现所有业务矛盾。实现范围内的普通技术选择交给成员；范围外和无证据项从严处理并记录缺口。

**增加候选身份与 UNKNOWN。** 每次评审绑定候选，未知不算通过；明确区分门禁没有执行结果与实际测试失败。

**计数拆分。** max_repairs 是首轮之外的业务返修；infra/protocol 各有总额度，且都消耗成员启动预算。格式修复不允许改代码。

**多单元集成显式声明。** 合作产物必须指定集成单元，不把局部通过直接当组合产品通过。

**通知是可失败的外围动作。** 桌面通知失败不会篡改已持久化业务结果，也没有手机推送。

**断点续跑采用新运行。** 同一未收尾运行只做故障收尾；主动 retry 新建运行，单单元可复用代码、重新验证，多单元保守重跑。不是恢复模型内部思考位置。

## 3. 未实现或有意不做

没有图形任务编辑器/实时网页控制台，只有 CLI 与离线 HTML 报告；没有观察员模型、模型缓存保温、自动改规则、动态拆任务、跨项目长期记忆库；没有真实成本/token结算；没有 Windows 原生进程树管理；没有自动 Git 合并/发布、数据库迁移或远程作业恢复。

原稿可选“累计达标加护栏”的跨次稳定性统计协议**未实现**。本版只判每个当前候选、当前门禁；不会挑历史成功样本拼成全通过。若有需求应另加试验计划、固定版本和完整尝试记录，不能在本版规则中伪造未支持字段。

总体安全范围仍是同账号防误操作：指纹不是强防篡改，不发现所有短暂改动。0.3.0 的显式本地 Pi 复用另有 macOS 系统级旧数据路径写保护（继承到 bash/Python、能力不足拒绝），不是全机器/原项目/网络隔离。实际工具 cwd 从自有 session header 持锁重绑，真实 CLI/账号与节省收益仍未验证，详见 [15](15-开发会话复用.md)。按本版的安全边界使用，不声称前次审查提出的每一项硬化都已经变成生产级实现。
