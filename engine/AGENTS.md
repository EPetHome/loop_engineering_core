# 给接手模型的操作说明

普通任务准备的入口是组合项目根目录 [AGENTS.md](../AGENTS.md)。本文件补充引擎范围的角色与开发边界，不要求先通读引擎 README、完整手册或配置参考。若拿到的是没有父级入口的独立引擎包，直接按下方短流程处理。

## 先判断自己在哪里

如果你正在与用户讨论任务，你和用户同属**拍板人**，在循环之外。你的工作是读需求、形成规则、准备命令、在停止后分析结果；不要替用户正式启动真实成员，不在运行期间用模型轮询或修改规则。

如果你被程序作为成员启动，并收到 `LOOP_CONTEXT` 或完整的本次 context，你在循环之内。以本次冻结规则和角色协议为准；不得调用调度、接管、重试、导出命令，不读写原项目与基线，不把本文件解释成你可以变为拍板人。

## 给用户准备任务

组合项目只遵循根目录 [短流程](../AGENTS.md)，这里不再维护第二套准备清单。

没有父级入口的独立引擎包：明确目标、授权范围、完成标准与预算 → 复用适用规则/测试（需要新建时用 `templates/task.template.json`）→ 必要检查和 `loop.py validate` → 给用户唯一 `loop.py run/start` 命令并结束准备。小任务可一个单元，有协作接口才安排集成；成员提示由 context 自动生成。关键业务缺口要解决，已授权的常规选择不逐项等确认。

字段/接法不清楚才查 `docs/03-规则配置参考.md` / `docs/04-成员工具接入.md` 对应节；程序/环境有变化或疑点才查 `doctor`，不把它当凭据、模型额度或全部运行冲突的证明。不预先实现成功解，不默认跑 demo、全引擎回归、假成员完整演练或真实模型试调用。首次接手的 LLM 不等于首次安装引擎。

## 停止后

先读指定运行的 `manifest.json`/`result.md`，按问题定位原始门禁日志。独立评审默认静态读取；执行 `status`、`audit`、测试或其他运行检查须符合本次用户授权。区分“记录观察”“分析推断”“未验证”。开发自评不是终态；评审 PASS 也不能盖过程序门禁失败。

用户认可后才能决定导出、比较、手工合并和更新项目基线。`export` 导出到新目录，不自动部署，也不代表用户验收通过。

遇到故障按 `docs/06-故障停止与恢复.md` 操作。不要把原运行改写成成功；不要私自 chmod、删除或编辑冻结记录来让 audit 变绿。`retry` 创建新运行，绝不继承旧 PASS。

## 继续开发引擎

入口 `loop.py`；模块说明见架构文档；运行 `python3 loop.py selftest`。运行中的引擎会检查自身 Python 文件指纹，因此**不能边跑真实任务边修改本目录引擎代码**。

改动必须给出测试与未覆盖风险。没有真实 CLI/账号实测就写“未实测”；不能用离线协议桩演示代替对真实模型能力、付费调用、生产项目的证明。
