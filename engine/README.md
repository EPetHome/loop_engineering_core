# Loop Engineering · 0.3.0

**启动一次 → 开发、自测、独立评审 → 必要时返修 → 停止交结果。**

这是根据你的九份设计文档和上一轮架构审查制作的本地首版实现，不是界面原型。它包含可执行调度器、静态依赖编排、进程监督、文件交接协议、三种停止结果、证据核对和中文手册。用户仍在循环之外定规则、启动、验收；引擎不替用户验收、不合并回原项目、不更新基线。

版本定位：**本地组合候选，未部署、不宣称真实项目生产验收。** 0.3.0 集成可信总收尾/正式导出、旧正文与问题证据交接、流式活动/可用用量，以及默认关闭的同单元开发业务返修会话复用。复用只支持组合交付的本地 Pi command 接法，持锁重绑实际工具 cwd 并用 macOS sandbox-exec 阻止旧 checkout/冻结候选写入；不支持则明确拒绝。fresh、评审和格式修复的新会话边界保留。

## 先运行一个不调用模型的例子

在终端进入解压后的本目录，然后执行：

```bash
python3 loop.py doctor
python3 loop.py demo
python3 loop.py status
python3 loop.py result
```

`demo` 使用可预测的本地成员程序，不调用 Pi、Codex 或付费模型，但实际修改代码副本、启动测试进程、产生返修与评审记录。预期结果是第二轮达标，业务返修 1 次、成员调用 4 次。

执行并行加集成的例子：

```bash
python3 loop.py demo --dag
```

系统要求：Python 3.10 或更新版本，POSIX 系统。引擎无第三方 Python 运行依赖，无需 `pip install`。Linux 的旧离线记录保留；本次 macOS 已进行离线进程/系统旧路径保护测试，但未验证真实 CLI/账号或生产业务；WSL 未实机验证，原生 Windows 不支持。可选 reuse_repairs 当前仅支持 macOS 有效 sandbox-exec，其他平台拒绝启用，fresh 不受此新增限制。不要用管理员/root 身份跑真实成员。

## 接入真实成员

内置 `pi`、`codex` 和通用 `command` 三种适配器。真实成员工具不随包附带，使用你本机安装并已登录的 CLI；没有内置账号或密钥。模型型号不写死，可在任务规则中明确填写。

```bash
python3 loop.py doctor --plan examples/real_pi_codex.json --check-tools
python3 loop.py validate examples/real_pi_codex.json
python3 loop.py run examples/real_pi_codex.json
```

上面的真实试跑需要本地 CLI、有效凭据和模型可用性；会调用你配置的模型。`doctor` 仅检查环境、程序是否存在和可选版本，不证明凭据、额度、模型或所有参数已兼容。包内真实适配器已实现并检查命令构造，**没有在制作环境中连接真实 Pi/Codex 账号跑通**。详见 [成员接入](docs/04-成员工具接入.md)。

## 结果不会藏在聊天里

默认数据在当前目录的 `loop-data/`。启动时打印运行编号、`result.md` 与 `report.html` 的绝对路径。`manifest.json` 是程序的权威记录，Markdown 和离线 HTML 是可重建的阅读视图。

```text
loop-data/
├── runs/<运行编号>/           规则、状态、交接、日志、结果
├── snapshots/<运行编号>/      冻结输入
├── checkouts/<运行编号>/      各成员、各门禁的独立代码副本
└── artifacts/<运行编号>/      分轮候选成果
```

同账号只读与指纹检查是防误改机制，不是全机器安全沙箱。显式复用接法另有系统级旧数据路径写保护，范围仅见 [15](docs/15-开发会话复用.md)；命令/Pi 成员仍具有其他本机进程权限；不应运行不可信项目、连接生产写接口或处理未经授权的外部动作。完整限制见安全文档。

当前实现状态以本 README、代码及测试为准；0.4.0 的整体用法见仓库根目录 CLAUDE.md 与 docs040/。
