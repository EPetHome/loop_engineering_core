# 接入自动验收：要复制进你项目的三块

> 自动评审的提示里说「把【块 N】复制到 …」，指的就是这一页下面的块。提示会写出你项目里的完整路径。
> 也可以一条命令接入（会先给你看要改什么，你确认了才写）：
>
> ```bash
> node /Users/Admin/Desktop/loop/setup-acceptance.ts <你的项目目录>
> ```
>
> 以后更新了 loop，再跑一次同样的命令即可：只替换下面标记之间的那一段，不碰你自己写的内容。

| 块 | 是什么 | 复制到哪 | 什么时候需要 |
|---|---|---|---|
| 【块 1】 | 验收标准的写法 | 项目的 `AGENTS.md` 末尾（Claude Code 见块 1 下面的表格） | 每个开了验收的项目都要；头脑风暴时模型才会把标准写进需求 |
| 【块 2】 | 被测系统怎么启动 | 项目的 `.autoreview.json` | 网页、接口这类要先启动服务的项目；命令行项目只写 `{"acceptance": {}}` |
| 【块 3】 | 浏览器工具 | 在项目目录里执行 | 验收要操作网页时 |

## 【块 1】验收标准的写法 → 复制到项目的 AGENTS.md 末尾

整段复制，包括首尾两行标记（以后更新时靠它们整段替换）：

````markdown
<!-- autoreview:acceptance v1：这一段由 loop 的接入手册维护，更新时整段替换 -->
## 起草需求时写验收标准（自动验收 v1）

用户让你起草需求、任务或提示词时，在末尾加一节「## 验收标准」：

- 每条写「操作」和「预期」：操作是用户从外部做的事（执行命令、打开页面、调用接口）；预期是外部看得到的结果（命令输出、页面内容、接口返回、数据变化、日志）。
- 一条只验一个行为，要有明确终点；不要写「处理所有边界」「完全正确」这类没法逐条核对的话。
- 只覆盖本次需求；代码结构、命名、性能这类不写。
- 不知道具体命令或地址时，操作写到行为层面即可，不要编造命令名。
- 最多 10 条，按重要程度排列。

格式：

## 验收标准
A1. 操作：执行 `todo add 买菜`
    预期：输出「已添加」
A2. 操作：重启服务后执行 `todo list`
    预期：列表里还有「买菜」

开发时不要补写或修改验收标准；验收标准只认用户发来的消息。
<!-- /autoreview:acceptance -->
````

放进哪个文件，看你用什么和模型头脑风暴：

| 你用什么 | 追加到哪里 |
|---|---|
| Codex、pi | 项目的 `AGENTS.md` |
| Claude Code | 项目的 `CLAUDE.md`；如果 `CLAUDE.md` 里有一行 `@AGENTS.md`，就追加到 `AGENTS.md`（Claude Code 不会直接读 `AGENTS.md`） |
| claude.ai 网页等项目外的对话 | 读不到项目文件：把这段贴到对话开头 |

## 【块 2】被测系统怎么启动 → 复制到项目的 .autoreview.json

网页、接口这类要先启动服务的项目，把下面的 `acceptance` 合并进 `.autoreview.json`（已有的其他字段保留），再按你的项目改三处：

- `start`：在项目目录里启动服务的命令。
- `readyUrl`：服务起来以后能打开的地址；程序访问它返回正常就算启动好了，启动前也用它检查端口有没有被别的程序占着。
- `env.PORT`：让服务监听这个端口（服务要认 `PORT` 环境变量；不认的话把端口直接写进 `start`）。

```json
{
  "acceptance": {
    "start": "npm run start",
    "readyUrl": "http://127.0.0.1:38080/",
    "env": { "PORT": "38080" }
  }
}
```

命令行工具这类不用启动服务的项目，只写 `{"acceptance": {}}`。其他可选字段（`logs` 收集日志文件、`guide` 操作说明、`timeoutMin` 等）见 [README.md](README.md) 的「自动验收」一节。

## 【块 3】浏览器工具 → 在项目目录里执行

验收要打开、点击网页时，验收方用无头 Chromium，需要 Playwright：

```bash
npm i -D playwright
npx playwright install chromium
```

不想装进项目，也可以全局安装 `playwright`，或者设置环境变量 `AUTOREVIEW_PLAYWRIGHT` 指向 Playwright 所在目录。

## 程序怎么认「## 验收标准」

- 只认**你发出的消息**里的 `## 验收标准`（单独一行的二级标题），到下一个一级或二级标题为止；模型写在回复里的不算。消息里的 `@需求.md` 会先展开再找。
- 条目可以写 `A1.`、`1.`、`- `，续行缩进；程序统一编号成 A1、A2…
- 定下后冻结。之后你再发一条带 `## 验收标准` 的消息，就替换成新一版；开发方和验收方都改不了。
- 需求里没写时不会卡住：第一次验收前由强模型只看需求原文起草一份，总结里标「自动起草，未经你确认」。
- 开发方觉得某条标准不对，会写「A2：异议：理由」，这时自动验收暂停，由你决定：同意就发新标准，不同意就让它按原标准继续。
- 头脑风暴定稿后，把需求（带 `## 验收标准`）作为开发会话的**第一条消息**发出去，比如 `@需求.md`。如果是在同一个会话里聊到定稿的，就把定稿的需求原文再发一次，程序才能取到标准。
