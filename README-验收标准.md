# ⚠️ 请在你项目的 AGENTS.md 里追加「验收标准」写法

> 这一页只讲一件事：把下面这段**追加到你自己项目的 AGENTS.md 末尾**（Claude Code 看下面的表格）。
> 这样以后你和模型头脑风暴、让它起草需求时，它会在需求末尾写好 `## 验收标准`，自动验收就按它来检查。

## 1. 复制这一段，追加到项目的 AGENTS.md 末尾

````markdown
## 起草需求时写验收标准（自动验收）

用户让你起草需求、任务或提示词时，在末尾加一节「## 验收标准」：

- 每条写「操作」和「预期」：操作是用户从外部做的事（执行命令、打开页面、调用接口）；预期是外部看得到的结果（命令输出、页面内容、接口返回、数据变化、日志）。
- 一条只验一个行为，要有明确终点；不要写「处理所有边界」「完全正确」这类没法逐条核对的话。
- 只覆盖本次需求；代码结构、命名、性能这类不写。
- 不知道具体命令或地址时，操作写到行为层面即可，不要编造命令名。
- 最多 10 条，按重要程度排列。

格式：

## 验收标准
A1. 操作：执行 `todo add 买菜`
    预期：输出「已添加」
A2. 操作：重启服务后执行 `todo list`
    预期：列表里还有「买菜」

开发时不要补写或修改验收标准；验收标准只认用户发来的消息。
````

## 2. 追加到哪个文件

| 你用什么和模型头脑风暴 | 追加到哪里 |
|---|---|
| Codex | 项目的 `AGENTS.md` |
| pi | 项目的 `AGENTS.md` |
| Claude Code | 项目的 `CLAUDE.md`；如果 `CLAUDE.md` 里已经写了 `@AGENTS.md`，追加到 `AGENTS.md` 即可（Claude Code 不会直接读 `AGENTS.md`） |
| claude.ai 网页等项目外的对话 | 读不到项目文件：把上面这段贴到对话开头 |

## 3. 为什么程序已经注入了还要追加

- 配了 `acceptance` 的项目，自动评审插件 / 扩展会在项目里的每个会话注入同样的约定。
- 但头脑风暴常常不在那样的会话里（还没开开发会话，或者在网页里），所以项目的 AGENTS.md 里也放一份。
- 都没写也不会卡住：需求里没有 `## 验收标准` 时，第一次验收前由强模型只看需求原文起草一份，总结里标「自动起草，未经你确认」。

## 4. 程序怎么认这一节

- 只认**你发出的消息**里的 `## 验收标准`（单独一行的二级标题），到下一个一级或二级标题为止；模型写在回复里的不算。
- 条目可以写 `A1.`、`1.`、`- `，续行缩进；程序统一编号成 A1、A2…
- 定下后冻结。之后你再发一条带 `## 验收标准` 的消息，就替换成新一版；开发方和验收方都改不了。
- 开发方觉得某条标准不对，会写「A2：异议：理由」，这时自动验收暂停，由你决定：同意就发新标准，不同意就让它按原标准继续。
- 头脑风暴定稿后，把需求（带 `## 验收标准`）作为开发会话的**第一条消息**发出去，比如 `@需求.md`。如果是在同一个会话里聊到定稿的，就把定稿的需求原文再发一次，程序才能取到标准。

完整的自动验收说明见 [README.md](README.md) 的「自动验收」一节。
