# Loop 运行与维护

权威入口：[README](../README.md)、[工具清单](../工具清单.md)、[任务/标准写法](../README-验收标准.md)。本页只说明执行职责、输入版本、资源及迁移，不记录接入项目运行状态，不替代用户标准或发布授权。

## 开发卡内核与迁移边界

`bin/loop 启动 <开发卡.json>` 一次校验并启动：开发评审 → 可选测试 → 可选验收 → 可选提交 → 可选部署。只评审卡为单任务 nature:评审、flow:[评审]。多任务必须统一验收及逐条责任归属；纯测试卡未上线。旧卡/开工/独立后置验收只有迁移诊断，旧执行器已删除，没有内部兼容或环境开关回退。

正常 `bin/loop 开发 pi|claude|codex` 保留单会话静态评审、原会话返修、用户真实输入、停止恢复、通知与证据。没有受管新卡身份时不自动提交用户目录，不运行配置验收或后置命令；未安排测试/验收写“没验证（本次未安排）”。Pi 非 Git/无提交时只关闭评审，不阻断开发；外部 Git 基线与旧项目资料不自动迁移。

内核由同一 node-ledger 记录候选、输入、用户版本、独立节点次数/时限、活动、票据、贡献、发布/部署及释放证明。查询/状态只读；同一候选重复宿主回调不双派发。停止不是放弃，不清零计数或发布事实。原会话续跑只认登记身份/信封；新讨论和真实补充要求不借旧候选交付。

### 窗口与任务身份

Pi 单/多任务默认每任务独立可输入 macOS Terminal 窗口；显式 --launcher background 才后台。--json 不是后台许可。续跑保留原会话、目录、次数和前后台偏好，停止只撤销一次性窗口请求。检查 worker 后台运输不改变开发选择。其他平台默认窗口不足明确报错；活动、待认领、未知身份不重复派工。状态分列任务与整批、真实执行/排队/返修/停点与释放；窗口存在不等于检查运行。

继承的 scope 增补沿改卡：一个任务一个已跟踪普通文件，真实用户确认具体任务/文件/卡版本，保留 deny、历史与成果。仅等责任任务，无关任务继续；原活 Pi 通过私有收件箱续接，PID 启动时间、session、launch ID 不符或信封过期则拒绝，不猜测杀进程。

## 执行职责与顺序

1. 用户明确目标、标准及节点/发布授权；协调方写任务提示词和开发卡，不替用户降低标准。
2. 启动先只读校验卡、路径、配置、localFiles、方法、标准归属和需要的部署输入，再登记隐藏工作区及宿主。方法自测使用原 methods.selfCheck，指纹未变跳过；失败不启动开发。准备检查/已知环境恢复及受限方法修复有独立预算，不走用户接管清零。
3. 开发方在原会话做受影响定向自检；程序提交 scope 内候选，再静态评审。测试只执行卡上原命令，验收只执行冻结范围。未安排节点不执行。
4. 多任务并行开发，任务检查到齐后按贡献装配。测试/验收共用本机 FIFO，排队不计时；统一验收失败仅回责任任务，集合到齐精确复验，不追加 full；首次及移出任务后的既定完整范围仍执行。
5. 提交节点只核对 validResult/输入/证据/贡献/授权，不暗查。正常只合入 dev、推 origin/dev；仅本地参数记录“未请求”，拒推保留本地事实、不自动重推。目标前进造成新树未检查须整合回原会话，不能用旧资格放行。
6. 部署仅在卡已安排且发布/推送成功后执行，配置与方法冻结，项目互斥、不占本机测试槽。失败重试须明确重跑部署，不重做前置检查或推送；安全回退仅本地 CAS，未知副作用保留现场。

例外合入使用同一 `bin/loop 合入 <卡> --接受未验证`，须真实用户确认当前候选及逐项欠项。决定绑定完整输入/用户版本/贡献映射；改标准或撤权后失效。例外不豁免未知来源、在途未提交成果和释放不明，不把没验证记成通过；多任务包含失败任务当前代码，不能漏发却声称整批已合入。无交集用户暂存/未暂存/未跟踪内容不 stash/reset；重叠拒绝。

## 项目配置示例

本机 `.autoreview.json` 不跟踪，加入本机忽略规则；真实脚本按项目替换。`bin/loop 接入 <项目目录>` 只处理配置，不下发稳定规则或旧约定副本。

```json
{
  "maxRepairs": 4,
  "reviewerModel": "openai-codex/gpt-6-astra",
  "reviewTimeoutMin": 60,
  "localFiles": ["local.txt"],
  "methods": { "paths": [".autoreview/methods"], "selfCheck": "sh .autoreview/methods/self-check.sh" },
  "preparation": { "check": "sh .autoreview/methods/prepare.sh check", "recover": "sh .autoreview/methods/prepare.sh recover", "timeoutMin": 5, "maxRecoveries": 1 },
  "acceptance": { "guide": ".autoreview/methods/GUIDE.md", "timeoutMin": 20 }
}
```

静态评审自身 budget 和验收执行器时限不比较、不共用；新卡用各节点 limits。原 gate 任意值忽略，不执行/校验/占预算，解析/轮询/查询不刷屏，实际新卡启动最多提醒一次。workflow/steps/workspaces 不决定流程或生成可见目录；merge.auto/push 不授予发布权限，旧值不自动删改。--release 已停用，不扩展成任意目标分支发布。

localFiles 只接受项目内普通本机输入；链接、父路径越界、用户暂存与配置内容变化都保护。方法配置、自检/探测、权限指纹仍使用同一来源；auto 与明确 deny 原样保留，不逐工具重新批准，不自动安装依赖。

## 静态规则、动态资料与变更记录

- AGENTS.md/CLAUDE.md 仅稳定边界，普通接入、归档、来源索引刷新不改它们。原需求/标准/授权保留，接入项目迁移单独授权。
- context.sources 显式声明需求、方案、方法及源码，内容版本和依赖变化写 changes.jsonl / contents/<SHA>；交付索引只导航，不成为新的业务标准。单会话来源内容变化更新并记录，缺失或配置移除阻塞；新卡真实引用冻结内容，不能续跑时自动追认新磁盘标准。
- 用户真实输入先保存授权/标准及原文，再做配置/Git/来源检查。文件块和机器返修信封不能冒充授权；追加真实撤权不能被信封吞掉。旧用户接管语义与机器重试分开。
- 问题单写法见 [README-验收标准.md「问题单」](../README-验收标准.md#问题单)。新卡不走旧开工预写或队列状态冲突消解；安全归档器、维护入口、正文/链接保护保留，不自动关闭原单。
- 经验候选/漏网案例保留来源与证据；用户批准才收入经验库，活动会话/未知消费者阻挡批准，不用清理抹掉失败。

## 验收复用与资源释放

acceptance.actions/guide、单轮 reset、纠错/报告恢复、实测工具与原始检查点继续使用。每次真实实测留证；恢复已提交检查点不等于恢复未输出推理。来源范围、标准/授权/配置变化核对后才能复用，自动未验证暂停，人工/拒绝授权单列，不能由程序改标准放行。定向成功没有第二轮 full 包装；首次和移出任务后的完整范围由内核既定计划决定。

- 测试命令在隔离 Git 候选执行。装配所有既有 ignored 输入/依赖，不以省略文件制造通过。默认均为输入；只有完整 Node I/O 证明未读取旧内容且完整替换的 ignored 普通文件才可记本次重建产物，源码/登记输入/依赖永不提升。重命名/别名读取、读后写、未知原生消费者及伪证据不放行。
- 原用户目录/索引/未跟踪/配置/标准/授权持续保护，瞬时写回也失效。产物不回写候选。CPython 缓存定向本尝试登记资源下 PYTHONPYCACHEPREFIX，不修改全局环境或旧缓存。
- 进程登记 PID/组号/启动时间/随机 owner/run/task/attempt。核对归属后才释放，未知端口占用者不杀。SIGKILL 无法当场 finally，不凭组长死亡或空登记宣布释放；缺结束回执/损坏登记/releaseUnproven 保留票据、检出和阻塞租约。
- test.json、check-workspace.json、attempt.json、interruption.json 与同账本 testWorkspaces 分列实测证据、原中断原因及旧结果保护原因。停止取得后续真实释放证明可结清具体未结项，旧未知枚举不永久自锁，也不能凭空核销。
- 准备/方法/测试/验收都有登记临时资源和独立证据目录。默认资源盘低于 256 MiB 拒绝昂贵检查，AUTOREVIEW_MIN_FREE_MIB 可调；准备恢复保留释放机会。项目 cleanup 幂等且只处理本轮测试库/容器/账号租约；失败阻挡推进。cleanup-task.json 留原方法、身份、状态和日志，不清理真实账号/生产数据。
- 缓存目录 AUTOREVIEW_TEMP_DIR 可释放；TMPDIR/EVIDENCE_DIR 独立保留证据。已完成会话按材料登记瘦身大运行文件及 node_modules，不碰源码、用户目录/共享缓存。保留结果、输入、日志、证据/检查点/图片/小文件与未知归属；符号链接、硬链接、消费者释放不明保留。删除失败仅提示，不追改业务结果。
- 历史先 `bin/loop 清理 --json` 只读预览，再明确 --apply。逐项核对原生状态和登记，状态变化就保留，不按名称/年龄/端口/PID 猜归属清理。

## PA 与历史记录

PA 沿既有请求编号/原文哈希/来源/会话协议；送话可读 stdin，同编号不重新读取/重发，sending/unknown 不重试，已读不等于检查通过。新卡按原任务及宿主通道投递并记同账本来源；伪头、错误会话、过期身份不授权。新卡续跑用现有内核入口；旧 pipeline 的重开分支已删除，只保留去重的迁移拒绝，不读旧 grant-file 再执行旧引擎。

query 只读历史 queue/phase/status/PA grants；不伪造新账本、不恢复旧发布意图。旧部署/队列可显式停止登记消费者，未知在途副作用单列，不按同名批次认领其他项目。旧记录、worktree 和历史文档不属于本次源码清理的删除对象。

## Ponytail 与 Skill

开发经 `bin/loop 开发 pi` 固定加载权限扩展、Loop 和 Ponytail（默认 full）；缺少指定文件报错，不自动安装。可显式关闭 Ponytail；运行时按实际命令检查，只提醒缺失，不改变检查结果。路径变化用 PONYTAIL_EXTENSION 指定并核对实际来源/版本。正确性评审/验收不受“少做”规则替代。Claude/Codex 沿各宿主已安装、启用和信任的 Hook/插件，不代信任、不改全局 auto/deny。没有真实对照样本不宣称成本下降百分比。

## 内部实现：兼容入口

bin/pi-dev 与 bin/loop-dev 保留正常单会话，setup-acceptance.ts 为接入配置工具。pipeline.ts 仅短迁移诊断，旧 parsePlan/dispatchBatches/runPipeline、段 workflow、开工装配、队列重检/免审/批次推送及独立 accept-cmd 执行均已移除。review.ts/hosts/review-hook.ts/autoreview.ts 不再调度验收或队列。acceptance.ts 保留 runAcceptanceOnce/内部单次尝试与收尾；workspace.ts 保留内核/部署所需 Git/归属；pipeline-core.ts 原子存储与历史状态被资料/方法/资源/来源/PA/宿主观测使用。merge-queue.ts/commit-batch.ts 只保留历史读取结构及安全停止，没有恢复或发布入口。历史路径重定位纯函数暂留，未接到任何启动/提交调用。

## 迁移与检查

新建 version:1 卡，将旧 stages 的提示词/scope 明确写 tasks，将 workflow/steps 换 flow，不填 workspaces；测试命令写 tasks[].test，不能把旧 full/accept-cmd/gate 搬成隐含检查。卡不必叫固定文件名；推荐开发卡.json，现有只评审报告配方也可只出报告，但不能混入旧段。不自动转换用户卡/配置或删旧目录，原标准与授权不重写。

开发用受影响的 node:test/kernel/host fixture、临时 Git 和本地 bare origin、隔离资源与通知根；不固定全仓集合，不安装依赖。实测程序、外层静态评审、真实装配、窗口体验和业务/人工验收分开记录。技术检查通过不是业务已验。本批不运行或修改 test/e2e.mjs，不补跑真实窗口、模型业务、浏览器、部署/远端或额外自动验收。
