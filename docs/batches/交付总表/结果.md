## A1 Pi 完成写入

**实现**
- `ledger.ts`：`appendLedgerRecord()` 按方案 3.1 拼一段（项目、任务、结果、总结、`- [ ] 已回写原单`、欠项）；欠项由 `pendingItems(AcceptanceRecord)` 从结构化验收结果生成，不解析总结文字；任务名取需求第一个标题，没有标题取前 40 字；项目路径记 Git 顶层目录。
- `autoreview.ts`：完成发布入口（`runReview` 的 done、`finishAcceptRun` 的通过、已完成会话重启恢复）调用 `recordLedger()`；同一完成态已登记时不重复追加，写入失败只提示，不暂停。`writeSummary()` 通过 `state.ledger` 在总结开头写「已登记到交付总表：<路径>；待回写原单（欠项）」。
- 发布顺序：先保存完成状态并写总表，最后才把总结改成「完成」。此前总结先于状态落盘，E2E 驱动看到「完成」就结束会话，可能抢在状态/总表写入前关掉 Pi（本次返修首轮 A1、A2 的 G5/A1-1 失败即此竞态）；现在同一条路径不会再抢跑。

**证据**
- `test/autoreview.test.ts` G16「完成写入」：A1 部分验证 + A3 人工；断言总表含项目、任务、结果、总结、已回写和两条欠项，总结开头含「已登记到交付总表」。
- 同测试「同一会话返修后再次完成」：第二次完成后只追加，不覆盖，总表出现两段。
- `test/ledger.test.ts` L1/L2/L3：段格式、欠项映射、任务名、追加不覆盖。

## A3 总表不可写时只提示

**实现**
- Pi `recordLedger()` 与 Hook `recordLedger()` 都捕获目录创建/追加异常；完成状态照常发布，只通过界面、stderr 或系统通知提示「交付总表写入失败」；总结写明失败和该检查的路径，不冒充已登记。
- 总表读取/格式异常在 SessionStart 也一律按「没有提醒」处理。

**证据**
- `test/autoreview.test.ts` G16「总表不可写」：总表位置被目录占住，最终仍 `done`，通知含「交付总表写入失败」和「会话照常完成」，总结含失败行。
- `test/hook.test.ts` H18「A3 总表不可写」：同样仍 `done`，不再暂停；stderr/通知有提示。
- 同测试「读取失败或格式异常」：SessionStart 退出 0，不注入提醒。

**未验**：真实宿主里系统通知的呈现（单测检查 stderr/通知参数）。

## A4 SessionStart 按项目提醒

**实现**
- `ledger.ts`：`parseLedger()` 解析段头和 `- [ ] / - [x] 已回写原单`；`pendingWritebackCount()` 只统计本项目、且只取同一会话最后一段；`writebackReminder()` 生成方案 3.3 的那句话。
- `hosts/hook.ts` `sessionStart()`：本项目有未勾段时把提醒追加到 `additionalContext` 末尾，并作为 Claude 的 `systemMessage` 给用户看；`ledgerNoticed` 保证同一会话只注入一次。没有待回写段时不追加；读取失败或超时跳过。Pi 的 `session_start` 没有这段逻辑。

**证据**
- `test/ledger.test.ts` L4：本项目两个会话（一个已勾、一个未勾）得到 1 段；别的项目 0；提醒文字含数量和路径。
- `test/hook.test.ts` H18：本项目提醒含「1 段待回写原单」和总表路径；同一会话第二次 SessionStart 不再注入；另一个 Git 项目不注入；没有 `待回写原单`。

**未验**：真实宿主的 SessionStart 注入时序和模型是否按提醒执行（单测为 Hook 子进程）。

- Pi / Hook 开始新一轮评审（或新的必需验收）时清掉旧的 `ledger` 登记标记，再次完成会追加新段。
