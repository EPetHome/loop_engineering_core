# 04 工作区与防篡改

用户的要求：

> 工作区这个概念也得继续保留着，因为是所有成员交接文档的地方。规则也应该存在，但是不得被其他员工所修改。防止篡改这些情况。

> 循环相关的一切都只落文档到他们循环这个范围内，基线不属于这个范围。

## 1. 工作区是什么

工作区是一个单元里所有成员交接文档的唯一地方。开发方和评审方不直接对话，每次都是新会话，只靠工作区里的文件传话。

三条原则：

1. **循环产生的文档只落在工作区。** 包括评审结论。
2. **基线不在工作区，循环里谁都不碰。** 结果要不要写进基线，由拍板人验收后自己决定。
3. **每个单元一个工作区。** 并行的单元互不写对方的工作区。

## 2. 工作区里有什么、谁能写

| 东西 | 内容 | 谁写 | 其他成员 |
|---|---|---|---|
| 规则 | 目标、边界、标准、何时停、停下交什么等 | 拍板人，启动前放入 | 只读，不得修改 |
| 交接 | 开发方的交付、评审方的结论，按次编号 | 开发方写交付；评审方写结论 | 不改别人的；不改旧的 |
| 状态 | 现在在哪一步、第几次来回、跑了多久、最近一次动静 | 调度程序 | 只读 |
| 结果 | 每次停止一份 | 调度程序和评审方 | 只读 |
| 日志与明细 | 各会话的输出、各自的分析材料 | 各写各的 | 只读 |

目录示意（不是固定格式）：

```text
工作区/<单元名>/
├─ 规则/          成员只读；启动时记下指纹
├─ 交接/          01-交付、01-评审、02-交付、02-评审 ……
├─ 状态           调度程序写
├─ 结果/          每次停止一份；最新的那份用固定名字
└─ 日志/          各会话输出、调度日志、成员的分析明细
```

开发方要改的产品文件不在工作区里。能改哪些，必须在规则的「边界」里逐个列明，列表之外的不许动。

## 3. 规则怎么防改

所有成员和拍板人用的是同一个系统账号，所以「绝对改不了」做不到。能做到的是三层：

| 层 | 做法 | 效果 |
|---|---|---|
| 防手滑 | 规则文件设成只读并加锁 | 普通的写入和编辑会失败 |
| 必被发现 | 启动时调度程序记下规则的指纹，每次交接都核一遍 | 一旦被改，当场停止，停止类型是「推不动：规则被改」 |
| 可恢复 | 规则的正本留在循环之外，工作区里只是副本 | 被改了从正本恢复，不影响判定 |

用户已确认这三层够用（2026-10-01）。

如果以后需要「连故意改都改不了」，要给成员单独的系统账号或沙箱，那是另一个量级的工作，目前不做。

同样的思路也用于「冻结」：验收期间不能变的文件，开始时记指纹，结束时再核。实战里用这个办法管住过 236 个文件。

## 4. 规则改版

规则只能由拍板人改，而且只能在循环停下之后改。

```text
循环停止（未达标，结果里有规则缺口）
      │
      ▼
拍板人验收时看缺口 → 修改规则正本 → 版本号加一，记下改了哪条
      │
      ▼
重新放入工作区，重新记指纹 → 重新启动
```

循环运行期间，谁都不改规则，包括拍板人。

## 5. 结果放哪，新会话怎么找到

用户的要求是：随时打开一个会话，查看结果就能拿到。

| 要点 | 做法 |
|---|---|
| 位置固定 | 每个工作区的结果目录里，最新结果用固定的文件名 |
| 多个单元有总览 | 一条命令把所有工作区的状态列成一张表 |
| 新会话能找到 | 启动前，由拍板人在项目基线里留一行指针：哪个循环、工作区在哪、结果看哪个文件 |

第三条不违反「循环不碰基线」：指针是启动前拍板人自己写的。

## 6. 评审结论和正式记录

评审方的结论只留在工作区。要不要把它写成项目的正式记录、要不要改基线，由拍板人验收后决定，并由拍板人自己写。

这一条改掉了 Promax 试行时的做法（当时评审方直接把正式记录写进了项目的验证记录）。用户已确认按新做法（2026-10-01）。
