# 运行材料按登记释放：留小证据，删大数据

## 目标

`~/.pi-autoreview` 已经有 6.7G，而且只增不减：

- `resources/evidence/` 占 2.7G，共 1073 个目录。门禁和验收脚本的 `TMPDIR` 被转存到这里（`resources.ts` 的 `managedShell`），设计上全部保留，没有任何到期规则。
- 验收运行目录（`<项目>/acceptance/<会话>/r<轮>/`）里留着测试库数据和依赖包，例如 Promate 每轮有约 117M 的 `mysql` 和 97M 的 `libs`，从来没有删过。

现在进程和端口已经按登记释放，磁盘上的运行材料却从不释放。背景见 `docs/方案-开发测试闭环.md` 第 6 节批 3。

## 已拍板

- **什么时候删**：开发会话变成「完成」时，对这个会话的所有轮次做一次瘦身。暂停中、进行中的会话一律不动（失败现场要留到问题处理完）。
- **删什么、留什么**：只处理 Loop 登记过、能证明属于这个会话的目录，也就是资源登记（`resources/*.json`）和这个会话的验收运行目录。
  - 保留：`result*.json`、`input.md`、`evidence/`、`checkpoints/`、所有 `.log` 文件和 `logs/`、截图（png、jpg），以及不超过 256KB 的脚本和文本文件。验收方写过的脚本以后要收编，所以要留着。
  - 其余删除：超过 256KB 的非保留文件、`node_modules`，以及删完后变空的目录。
  - `resources/evidence/<id>` 按同样的规则瘦身。
- **历史存量**：新增 `loop 清理`。默认只列出要删的路径和能腾出的空间，加 `--apply` 才真正执行。规则同上，只处理已经「完成」的会话。
- **不能猜**：不按名字、修改时间、端口或进程号推测归属。归属不明、没有登记或登记对不上的，一律保留，并在输出里列出来。
- 瘦身结果写进总结，一行说明：删了多少文件、腾出多少空间、保留了哪些。删除失败只提示，不改变会话的完成状态。

## 边界

- 涉及的代码主要在 `resources.ts`、`acceptance.ts`、`loop.ts`（新增子命令），以及会话完成时调用它们的地方（`autoreview.ts`、`hosts/hook.ts`）。测试放在 `test/`，全部在系统临时目录里造数据，不碰真实的 `~/.pi-autoreview`。用法同步到 `工具清单.md` 的 `bin/loop`，以及 `项目文档/运行与维护.md` 的「E2E 复用与资源释放」。
- 开发期间不要对真实的 `~/.pi-autoreview` 执行 `loop 清理 --apply`，只能跑不带 `--apply` 的版本来核对输出。
- 不改 `review-prompt.md`，不改 `test/e2e.mjs` 的场景和断言，不改 `eval/`、`iusses/`、`temp/`。
- 不提交，不推送。

    预期：大文件和 `node_modules` 被删除；证据、结果、日志、截图和小脚本都还在；总结里有瘦身那一行。
