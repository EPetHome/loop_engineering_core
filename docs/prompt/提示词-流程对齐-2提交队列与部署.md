# 流程对齐 2：自动推送、队列自动提交、部署

## 目标

现在的情况：

- 批次完成后只在本机提交，推不推还要再问用户一次。
- 合入队列每次都把全套测试重跑一遍（Loop 自己要 10.5 分钟），测完停在「可合入」，等用户开口。
- 队列测试超时，会被报成「与已合入批次冲突」退回开发会话（`merge-queue.ts` 门禁失败那个分支），开发方去查一个根本不存在的代码问题。
- 没有部署这一步。

本段要做到：

- 测试、验收都通过后，自动推送批次分支。
- 队列不做重复测试，测完自动提交到目标分支。
- 测试超时如实通知用户。
- 新增部署环节，默认关闭。

## 已拍板

- 用语约定：「提交」是在分支上提交；「推送」是推到远端仓库。Loop 不碰 main，main 由用户自己合。
- 批次完成（该跑的测试、验收都通过）后：
  - 程序在本机把整批压成一个提交，沿用现有的 `commit-batch`。
  - 然后自动把批次分支推到 `origin`。复用 `loop 推送` 的逻辑：不推目标分支、不强推，记下推送的提交号。
  - 推送失败时保留本机提交，通知写明原因，不强推重试。
  - 通知里不再问「要不要推」。
- 合入队列（一个目标分支一个队列，逐批处理）：
  - 本批开工后目标分支没有新提交时（合并结果和本批测过的版本是同一棵树），不重跑测试，直接沿用本批自己的测试结果。记录和通知里写明沿用的是哪一次测试。为此，段完成记录要带上测试结果和测过的版本。
  - 目标分支有新提交时，照现在的做法测「最新目标分支 + 本批」。
  - 测试通过后自动提交到目标分支：沿用现有 `mergeLocked` 的核对和比较交换，不重新计算合并，不需要用户执行 `loop 合入`。`loop 合入` 命令保留，用于手动场景。
  - 目标分支是 `main` 或 `master` 时不自动提交，停在「可合入」，通知写明「main 由你自己合」。
  - 目标分支不推远端。
  - 队列测试超时：通知用户「测试超过时限（N 分钟）」，附日志路径和调整方法。不退回开发会话，不计退回次数，不写「与已合入批次冲突」。
  - 冲突、真实的测试失败退回原段，这套现有机制不变。
- 部署（做好，但默认关闭）：
  - 项目配置新增部署命令、部署后检查命令和开关，开关默认关。
  - 打开时的顺序：自动提交到目标分支 → 等同一项目里没有批次处在评审、测试、验收中 → 执行部署命令 → 执行检查命令。
  - 检查失败时：目标分支退回本批之前的提交（复用 `loop 撤回` 的比较交换），再执行一次部署，恢复上一版；通知用户失败原因和已回退。退回不了时只通知，不再动任何东西。
  - 没打开时不执行任何部署，总结和交付记录写「部署：未开启」。
- 旧配置里的 `merge.auto`、`merge.push` 仍然只提示、忽略；提示文字改成和新行为一致。

## 边界

- 在第一段完成后的批次分支上继续。
- 相关位置以开工时的代码为准：
  - `commit-batch.ts`
  - `loop.ts` 的 `cmdPush` 和撤回
  - `merge-queue.ts`：门禁运行、失败退回 `returnToDeveloper`、`mergeLocked`、`notify`、写交付记录
  - `config.ts` 里 `merge.*` 的兼容提示
  - `pipeline-core.ts` 的段完成记录
- `README.md` 的「配方怎么选」「开工、启动、状态与合入」「合入队列」等节，以及 `工具清单.md`，同步更新。「问推不推」「只有用户执行合入才更新发布分支」这类旧说法全部改掉。
- 改了已有测试的断言时，交付时列出改了哪些、为什么改。
- 不改：评审和验收提示词、`test/e2e.mjs`，以及第一段定下的流程顺序和开工检查。
- 远端用系统临时目录里的裸仓库；部署命令和检查命令用替身脚本。
- 测试按功能命名；不新增名字里带「返修N」「本批」的测试。
- 开发方不提交。

## 验收标准

A1. 操作：单段批次测试、验收都通过后完成
    预期：批次分支在本机提交，并推到远端（临时裸仓库）的同名分支；通知里没有「要不要推」
A2. 操作：远端的批次分支已经分歧，批次完成
    预期：本机提交保留；通知写明推送失败及原因；没有强推
A3. 操作：本批开工后目标分支没有新提交，批次进入队列
    预期：队列没有重跑测试，记录写明沿用本批的哪次测试；随后自动提交到目标分支
A4. 操作：本批开工后目标分支已有别的批次的提交，批次进入队列
    预期：队列测试「最新目标分支 + 本批」；通过后自动提交到目标分支；远端的目标分支没有变
A5. 操作：目标分支配成 `main`，批次通过队列测试
    预期：没有自动提交，停在「可合入」，通知写明 main 由用户自己合
A6. 操作：让队列测试超过时限
    预期：通知用户测试超过时限，附日志路径和调整方法；没有退回开发会话；没有出现「与已合入批次冲突」
A7. 操作：没有打开部署，批次自动提交到目标分支
    预期：没有执行任何部署命令；总结写「部署：未开启」
A8. 操作：打开部署，另一个批次正在评审中，本批自动提交到目标分支
    预期：部署等那一批评审结束后才执行；执行后跑检查命令，检查通过则通知已部署
A9. 操作：打开部署，让检查命令失败
    预期：目标分支退回本批之前的提交，并重新部署上一版；通知写明检查失败原因和已回退
