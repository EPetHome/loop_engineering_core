## 七、设计约束（陷阱）

1. **B1-a 的身份口径要和 `finding_id` 一致**。不要自己再发明一套比较方法（例如去空白、忽略大小写），否则协议和台账又会出现两套标准。
2. **M1 的覆盖判断用相对路径**，按 POSIX 斜杠比较。不要用 `in` 去匹配文件名片段，比如 `a.py` 会误匹配 `data.py`。判断标准是：路径前后不能紧挨着路径字符（字母、数字、`_`、`-`、`.`、`/`），或者用其他同样严格的写法，并在简报里说明。
3. **M1 拒收会消耗协议重试次数**。`max_protocol_retries` 不改，但简报里要写清：地图漏写会消耗一次协议重试，次数用完单元就会 BLOCKED。
4. **先评审的轮次**（`first_round=review`）没有开发交付，`code_map` 是 `null`，这时 M1 不运行，M2 是「无地图」。在 `test_repair_merge040.py` 现有的先评审场景上确认不会报错。
5. **B2 和 M2 共用读取路径**。B2 置为 `None` 后，M2 也必须是 `None`，不能用空数组算出 0。
6. 提示词文字只允许改 M1-g 那一句。改完后用 `test_repair_merge040.py` 里的 `instruction_blocks()` 输出前后对比，简报附上改前和改后那一句的原文。
