# 流程配方：只评审配方，以及 PA 用的执行命令

现在有两个缺口：

- 评审结论只能打回给开发会话。没有「没人接、只出报告」的入口，所以「只评审一段已有改动」做不了。
- PA 替用户点了确认以后，要调用 Loop 去推送、合入、停批次，并拿回结构化的结果。

本段要补上：「只评审」配方，加上 `loop 合入`、`loop 推送` 的固定 JSON 输出，再新增 `loop 停止`。

## 已拍板

- **配方字段**：
  - `批次.json` 新增 `recipe`，取值是 `"develop"`（默认）或 `"review-only"`。写了别的值就报计划错误，退出码 3。
  - `loop 启动` 按 `recipe` 分派。
  - `review-only` 不需要先开工。
- **`loop 评审 --base <提交或分支> --head <提交或分支> [--requirement 文件] [--criteria 文件] [--note 文件] [--json]`**：
  - 批次写法是 `{ "recipe": "review-only", "review": { "repo", "base", "head", "requirement", "criteria" } }`，效果和命令行一样。
  - 在系统临时目录新建一个分离的 worktree，检出 `head`。结束时一定释放，出异常也要释放。原工作区不碰。
  - 新建一个 `ReviewState`：`baseline` 设为 `base`，不跑门禁，不跑验收，`maxRepairs` 设为 0。
  - 调用现有的 `runReviewRound`。
- **review.ts 的结论去向**：
  - `ReviewDeps` 新增 `sink?: "repair" | "report"`，默认是 `repair`，也就是现在的行为。
  - `report` 模式下，有必修或无必修都返回 `{ kind: "report", review, record }`。
  - `report` 模式下跳过这些：进合入队列、记经验复发、写交付总表、写收件箱。
  - 评审提示词、解析、重试、超时预算、资源释放全部复用，不另写一套。
- **只评审的产出**：
  - `~/.pi-autoreview/reports/<ID>/report.md` 和 `report.json`。内容包括基线、候选、改动文件、必修（含触发条件和后果）、建议、模型、耗时。
  - 退出码：0 表示没有必修；1 表示有必修；2 表示评审失败或超时。
  - 事件：开始时发 `started`。结束时发 `done{recipe:"review-only", report}`，失败时发 `failed`。
- **执行命令的 JSON**：
  - 统一外壳是 `{ v:1, ok, action, …, reason{category,text} }`。
  - `loop 合入 --json` 另外固定带 `release`、`merged`（提交号）、`queueStatus`。
  - `loop 推送 --json` 另外固定带 `branch`、`remote`、`pushed`（提交号）。
- **`loop 停止 <批次.json> [--stage <段>] --json`**：
  - 按段状态里记录的宿主、pid 和启动时间核对进程身份，核对上了才结束它的进程组。
  - 释放登记的资源。
  - 合入队列里本批的条目标成「已停止」。
  - 发 `failed` 事件，`reason.category` 写「已停止」。
  - 不删工作区、分支、总结和证据。
  - 身份核对不上的进程不碰，并在结果里列出来。
  - 不按端口、文件名或进程年龄去猜归属。
