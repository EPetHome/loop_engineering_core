# 共用验收隔离：独立自动验收操作说明

本说明供准备批 S 的独立验收方使用。它是尚待执行的方法，不是通过记录。只操作本轮生成的临时样本；不运行本仓库单测代替验收，不导入候选的内部函数，不启动真实内层模型，不清理历史演示数据。

## 入口与保护范围

待验公开接口为：

```text
node <候选根>/acceptance-tools/isolated-loop.mjs --target <候选根> --evidence-dir <报告目录> --label A1 [--write-path <相对内层根的路径>] [--timeout-sec N] -- COMMAND ARGS...
```

这项接口由 S 实现，当前说明不能证明它已存在。每次调用应新建内层根，向命令提供 `LOOP_ISOLATION_ROOT`、`LOOP_CANDIDATE_ROOT`，工作目录为内层根。最终输出 `ISOLATION_REPORT=<JSON路径>`；报告字段为 `root`、`paths.home/queues/resources/projects/agent/paEvents`、`commandExitCode`、`processesReleased`、`rootReleased`、`stdoutLog`、`stderrLog`。命令失败应保留原退出码；失败或保留现场时 `reason` 必须非空；释放无法确认必须非零。

独立外层入口已由协调方提供：

```text
/Users/Admin/Desktop/loop/.autoreview/methods/acceptance-outer.mjs
```

调用时必须传入准备交接记录中的 `e807ca89c2006b7fbae79be87b1061fe4fb8ca812fe82a93386650f532a1b536`。该脚本与候选分开维护，候选不得修改。外层给子进程建立私有 HOME、状态根、PA 配置和受控临时目录，并由可信执行器独立收尾。**这不是操作系统写入沙箱，不能声称可防止任意恶意候选写文件。**因此全部越界反例只能指向外层根内的哨兵，不能传真实 HOME、真实状态或项目资料路径。

候选报告写在 `<outer>/reports`；场景程序在外层收尾前读取并输出报告全文、原始日志和观察结果，外层随后保存到正式验收目录。不能让候选直接管理正式证据目录或外层资源。

## 准备场景文件

};

本脚本中的独立消费者使用 `detached:true`、`unref()`，另设自己的 `AUTOREVIEW_PROCESS_OWNER` 和随机 `S_ACCEPTANCE_CONSUMER_TOKEN`，保留 `LOOP_ISOLATION_ROOT`，记录 PID、`ps` 起始时间及持续心跳；不是普通同步子进程。它最多运行 15 秒后自退；自退有明确记录，不能计作候选清理成功。

观察发生在候选 CLI 返回后、场景程序退出前。候选漏清理时先输出 `CANDIDATE_SCENARIO_FAILURE`，随后场景的 `finally` 依据自己的启动登记、PID 起始时间、独立 token 和 owner 核对身份，再终止自己创建的消费者。这是观察者兜底，不能把候选失败改为通过。身份或释放仍无法确认时写 `<outer>/outer-retain.json` 并非零退出，外层据此强制保留现场、不宣称资源已释放。不能依赖外层按直接父 owner 找到已经换 owner 的孤儿，也不能按 PID 猜测清理。

## 逐项判定

| 条目 | 必须看到的实际证据 | 不能作为通过依据 |
|---|---|---|
| A1 实际状态落盘 | 公开 `开工`、`启动` 的原始结果；真实 queue/pipeline/events/PA 文件和内容；公开 Hook 本样本交付记录；实际路径与候选报告一致且在内层根；正式证据由外层保存 | 手动创建几个同名状态目录、静态环境变量清单、单测总数 |
| A2 越界输入拒绝 | `../sentinel`、绝对哨兵路径、外层内指向该哨兵的符号链接入口均非零拒绝；`payload-entered` 不存在，哨兵未变；错误指出越界输入 | 向真实 HOME 写探针、候选先写再清理、只看最终目录不存在 |
| A3 同名并行与连续 | 两轮同时运行、第三轮接续，同名但根、报告和实际数据随机身份均独立 | 只串行两次、名称不同便认定隔离 |
| A4 成功/失败/超时/取消 | 成功 0、失败忠实保留 23、2秒时限耗尽和主动取消均非零；每次消费者确实启动并在候选返回前后结束，兜底前已观察退出和心跳停止，未靠15秒自退；成功释放根，失败可保留根但reason非空且现场确实存在 | 仅 `processesReleased:true` 自报、outer最终收尾成功、消费者自然到期或观察者兜底成功、普通同步子进程退出 |
| A5 通知与后台继承 | 真实 Loop 事件写私有 PA 目录；配置真实存在且 localNotify=false；独立消费者读到同一私有环境与关闭通知配置；后台进程已结束 | PA配置路径不存在、仅有父进程env、后台未实际启动 |

A1 的 `start:'true'` 用于验证真实启动登记，不表示内层开发完成；交付记录单独由公开 Hook 协议产生。HOME下events目录核对事件序号等JSON元数据，事件JSONL在私有PA接收目录核对，两者不混用。内层假模型不能证明模型语义或真实宿主装配。后台独立消费者用于此次收尾条件，不冒称已经覆盖真实Terminal；A5同时核对清除TMPDIR后的实际临时目录仍在私有根内。

A2 的符号链接反例是“外部符号链接入口被拒绝”，其入口和目标都在 outer 内。当前 CLI 每次新建 inner，未提供预置并复用 inner 的接口，故不通过竞态写入去伪造“内层已有相对符号链接”场景；不能把本反例扩大表述为全部相对链接解析边界已实测。

“真实状态无本轮样本”由受控输入与实际落点共同核对：脚本不读取、比较或删除真实状态树，不将其他活动任务的变化归责于本轮。外层没有操作系统写入边界；若候选明显包含受控场景以外的写入行为或固定真实路径，先停止并报方法/候选风险，不冒险运行后再看是否污染。

每条结论引用本次 `evidence/A*.txt` 的原始摘录及外层 `<A*>-outer-*.json`。外层释放成功只说明兜底收尾结果；S 自身是否通过取决于上述外层收尾前的观察。遇到无法确认的进程归属、缺失公开报告或缺失实际状态文件，保留未通过/无法验证及原文，不能按“脚本跑完”判全通过。
