# 问题单统一

## 目标

Loop、Promate、personal agent 三个项目各有一套问题单写法（叫法、正文结构、状态、修完怎么处理、什么时候开批都不一样），规则散在各项目自己的 `AGENTS.md` 里；修完以后靠人工把文件挪进 `【已完成】` 表示完成，没人负责关单，链接也会被挪断。完整事实、三个项目的对比和统一写法见问题单 `/Users/Admin/Desktop/loop/iusses/问题单目录改名issues并按GitHub方式补齐关单闭环.md`（只读）。

本批做 Loop 这一侧：

1. 把统一的问题单方法写成**唯一一份**，放在 Loop 的 `README-验收标准.md`；项目模板照着用。
2. 批次可以登记「本批修哪几张单」。登记的单子在本批合入目标分支时，单头状态随本批提交一起变成「已合入待验·<批次名>」。

目录改名、迁移现有单子、改三个项目的 `AGENTS.md`、改 `eval/经验/采集.py`，由协调方在本批合入后另做，不在本批。

## 已拍板

- **方法论全部统一，只在 Loop 维护一份**：写在 `README-验收标准.md` 新增的「问题单」一节，内容按问题单「预期结果」里的统一写法表和正文模板，不另起写法。各项目和 `项目模板/` 不留副本，只写一句指向这一节（用户 2026-11-04）。
- 状态只有四种：待修复 → 修复中·<批次名> → 已合入待验·<批次名> → 已解决（写关闭原因：完成／重复／不做）。状态写在单头，**不挪文件夹、不改文件名**。
- 问题单目录名为 `issues/`（项目根下，所有单子同一层）。
- 单头状态的回写**随本批提交一起进入目标分支**：目标分支上不留下未提交的改动，也不另外追加提交（用户 2026-11-04 定「跟合入提交一起提交」）。
- 回写是附带动作，**不新增卡点**：登记的单子不存在、不在仓库里、写不进去，都只在开工输出、总结和交付总表里提示，不拒绝开工、不退回、不阻止合入。
- 改成「已解决」要用户验收，由协调方写；程序不自动关单。

## 边界

- 基于合入「流程对齐」之后的 dev（`e5c67a4`）开发。
- **不能改坏的行为**：
  - 合入队列发布的必须就是测过的那个提交（`merge-queue.ts` 的 `mergeLocked`，比较交换到测过的提交，不重新计算合并）；
  - 部署要求目标分支仍停在该次提交上；
  - 整批压缩不改变树，提交前后核对的候选树不能变。

  所以不能在合入时或合入后对目标分支追加回写提交，也不能在测过以后改候选树。建议的做法：开工搬运批次文档时，把登记单子的单头改成「已合入待验·<批次名>」，随「批次文档」提交进入批次分支。这样测过的树里已经包含回写，合入即生效，撤回即恢复。若有更好的做法，只要满足上面三条和「已拍板」的要求即可。
- 「已合入待验」的单头同时写明未验证项去哪里看：本批交付总表或总结（交付总表本来就逐条列出人工未验项）。
- 登记的单子在仓库外（Promate 的问题单不在代码仓库里），没法随提交进入：开工时不写；合入目标分支成功后，直接改该文件的单头；失败只提示。
- 新字段写进 `工具清单.md`「批次.json 字段」；README「流水线与批次」提一句即可，不复制字段表。
- `项目模板/项目根/` 增加 `issues/`（可放一份按统一模板写的示例或空目录说明）；模板 `AGENTS.md` 只写一句指向 `README-验收标准.md`「问题单」一节；`项目模板/README.md` 第 73 行「模板没放：问题清单 `iusses/`」改为已放 `issues/`。
- 不改：`docs/`、`iusses/`、`issues/`、`eval/`、`temp/`、`test/e2e.mjs`、`review-prompt.md`、`.autoreview.json`、`AGENTS.md`；不改评审和验收的判定规则、验收标准的解析规则。
- 测试放在 `test/`，用系统临时目录里的临时仓库；复用现有合入队列、开工的测试夹具。
- 开发方不提交。

## 验收标准

A1. 操作：打开 `README-验收标准.md`
    预期：有「问题单」一节，写明目录 `issues/`、单头三个字段（状态、排期、关联单）、四种状态和三种关闭原因、正文八个小节的模板、建单和开批规则、部分完成和重复的处理、合入回写和关单由谁做、不挪文件夹不改文件名
A2. 操作：打开 `项目模板/项目根/AGENTS.md` 和 `项目模板/README.md`
    预期：模板 `AGENTS.md` 只有一句指向 `README-验收标准.md`「问题单」一节，没有自己的问题单规则；`项目模板/README.md` 不再写「模板没放：问题清单」，也不再出现 `iusses`
A3. 操作：临时仓库里提交一张单头为「状态：修复中·示例批次」的单子，批次登记这张单，执行 `bin/loop 开工 <批次.json>`
    预期：开工成功；批次分支的批次文档提交里，这张单的状态行变成「已合入待验·示例批次」，并写明未验证项去哪里看；发布分支上这张单不变，运行版没有未提交的改动
A4. 操作：接着让这一批完成并经合入队列合入目标分支
    预期：目标分支上这张单的状态是「已合入待验·示例批次」；目标分支指向的提交就是队列测过的那个提交，没有额外的回写提交
A5. 操作：批次登记一张不存在的单子，执行 `bin/loop 开工 <批次.json>`
    预期：开工照常成功，输出里提示这张单找不到、不会回写；后续合入不受影响
A6. 操作：批次登记一张仓库外的单子，让这一批完成并合入目标分支
    预期：合入成功后，这个仓库外文件的状态行变成「已合入待验·<批次名>」；把文件设为只读再跑一次，合入照常完成，总结里提示没写进去
A7. 操作：对 A4 合入的批次执行 `bin/loop 撤回 <批次.json>`
    预期：目标分支回到合入前，这张单的状态回到「修复中·示例批次」
A8. 操作：批次登记的单子在本批进行中被人改了别处的正文（不碰状态行），本批完成合入
    预期：合入不因这张单产生冲突退回；目标分支上正文的修改和状态回写都在
A9. 操作：打开 `工具清单.md`「批次.json 字段」
    预期：有登记问题单的字段，写明类型、路径怎么解析、仓库内和仓库外分别什么时候回写、失败只提示不阻断
