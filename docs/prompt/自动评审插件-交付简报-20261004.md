### 3.2 宿主识别（派单方案的修正）

派单建议「有 `turn_id` 就是 Codex」。实测 Codex 的 SessionStart 不带 `turn_id`，会被误判成 Claude，导致 SessionStart 写的状态与 UserPromptSubmit/Stop 用的状态分成两个文件（`claude-…` 与 `codex-…`），「非 git 仓库关闭」等会话级状态会失效。已改为：

1. `AUTOREVIEW_HOST` 强制指定；
2. 有 `turn_id` → codex；
3. 环境变量 `CLAUDECODE` / `CLAUDE_CODE_ENTRYPOINT` → claude；
4. 环境变量 `CLAUDE_PLUGIN_ROOT`（Codex 的 Claude 插件兼容层会设，Claude 也设）→ codex；
5. `transcript_path` 含 `/.codex/` → codex，含 `/.claude/` → claude；
6. 默认 claude。

修复后重跑 Codex 真实评审，只生成 `codex-…` 状态文件（已验证）。

### 3.3 timeout 实际上限与生效方式

- hooks.json 的 `timeout` 单位是秒；`SessionStart`/`UserPromptSubmit` 10 秒、`Stop` 3700 秒。
- **Claude Code 从仓库源目录读取**插件 hooks.json（debug 日志：`Read hooks.json for plugin autoreview … /Users/Admin/Desktop/loop/plugins/autoreview/hooks/hooks.json`），改仓库立即生效。
- **Codex 从插件缓存副本读取**（`~/.codex/plugins/cache/autoreview-local/autoreview/1.0.0/hooks/hooks.json`），改仓库后需重装/刷新缓存才生效。
- 5 秒反向实验证明两个宿主都严格按配置的 timeout 执行，没有把 5 秒改大；90 秒睡眠正常通过，说明没有低于 90 秒的硬上限；3700 秒无法在合理时间内直接实测（按配置生效推断，且宿主未报错）。Hook 内部评审保护默认仍是 60 分钟，可用 `.autoreview.json` 的 `reviewTimeoutMin` 或环境变量 `AUTOREVIEW_REVIEW_TIMEOUT_MIN` 调低。
- 宿主超时杀掉 Hook 后，锁文件留 pid；下一次 Stop 判定死进程 → 「评审被中断」暂停并通知（两宿主实测）。

### 3.4 Codex 信任机制

- 未信任时 Hook **静默不执行**（连 SessionStart 都没有），不会报错、不会阻塞。
- 需要在 Codex 里用 `/hooks` 确认信任；信任哈希写入 `~/.codex/config.toml` 的 `[hooks.state."autoreview@autoreview-local:hooks/hooks.json:<事件>:0:0"]`。
- 自动化场景可用 `codex exec --dangerously-bypass-hook-trust`（本次 E3/E4/E5 即如此，如实记录）。

### 3.5 `stop_hook_active` 的表现

返修后的复评发生在 `stop_hook_active=true` 下；Hook **不因它跳过评审**（E1/E3 第二次 Stop 都完成复评并放行）。死循环由返修上限兜住（H5 已测）。

### 3.6 追加需求（不靠标记自动评审）

- `CONVENTION` 新原文：交付时最后一行写【交付完成】，评审会立即开始；不写的话，程序检测到改动也会自动评审。需要用户决定时，最后一行写【需要你决定】。收到自动评审消息后，逐条写「第 N 条：已修」或「第 N 条：异议：理由」。
- pi 与宿主行为一致：停下时比较工作区指纹（与上次成功评审的 `lastFingerprint`，没有就与开发基线）；有变化→直接评审；无变化且 `awaitingRepair`→暂停「返修后没有任何改动」；无变化且非返修→不动作；暂停状态不自动评审。
- 「未交付提醒」已删除（含 `remindedFingerprints` / `notifiedFingerprints`）。
- 评审时间预算：首次调用加 1 次重试共用 `reviewTimeoutMin`（默认 60 分钟）；重试只能用剩余时间，剩余不足 1 分钟不重试并暂停「评审超时」（`test/review.test.ts` 用注入时钟验证）。
- `hooks.json` 未改动，Codex 信任哈希不受影响；两边仍直接执行仓库里的 `hosts/hook.ts`。
- 实测 `pi -p`（非交互单轮）：会话在评审完成前退出，评审被中断并写暂停总结；pi 日常交互与 RPC 常驻会话正常自动评审。
