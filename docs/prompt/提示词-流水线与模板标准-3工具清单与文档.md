# 流水线与模板标准 · 第 3 段：工具清单、一致性测试、模板和文档

## 目标

协调方模型每次开工前都要读两份 README，有时还要读 loop 源码，才能知道怎么用 loop。本段给模型准备一份可以直接用的工具清单，并用测试保证清单和代码一致。同时把项目模板和文档改成第 1、2 段之后的新做法：

- worktree 开发空间；
- 项目方法写在 `.autoreview/methods/`，只写一份；
- 每批只写 `批次.json` 和提示词；
- 开工、启动、状态、合入用 `bin/loop` 完成。

设计依据是 `docs/方案-流水线与项目模板标准.md` 的第 4.5、4.1、4.2 节。先读 `docs/batches/流水线与模板标准/结果.md` 的第 1、2 段，以那里实际实现的命令和字段为准；方案和实现不一致的地方按实现写，并在结果里列出来。唯一结果写入同一文件的「第 3 段」一节，逐条列出 A1–A6 的实现、证据和未验证的内容。

当前工作目录是本批唯一授权的隔离检出。开始时先用 read 读 AGENTS.md、方案和前两段结果，用 bash 执行 `pwd`，然后自主推进，不要每一步都停下等批准。

## 已拍板

- 工具清单放在仓库根目录，文件名 `工具清单.md`，读者是协调方模型。每个工具一节，写清：
  - 名称和用在哪个阶段；
  - 做什么；
  - 输入：参数，以及用到的 `批次.json` / `.autoreview.json` 字段；
  - 输出：`--json` 的字段；
  - 失败分类和退出码；
  - 会改哪些文件。

  覆盖 `bin/loop` 的全部子命令、`bin/pi-dev`、`pipeline.ts`、`setup-acceptance.ts`、`project-context.ts`，以及项目方法能拿到的环境变量。另外单独一节列出 `批次.json` 和 `.autoreview.json` 的全部字段：类型、默认值、作用。
- 一致性测试：从代码里取子命令列表和字段的解析定义，和清单对照。任何一边新增或删除了，另一边没跟上，测试就失败，失败信息说明缺了哪一项。
- 项目模板（`项目模板/`）改成新做法：
  - 开工步骤 ⑤ 改成「写 `批次.json` 和提示词 → `loop 开工` → `loop 启动`」；
  - 批次目录里不再放门禁、棘轮、启动脚本；
  - 新增 `.autoreview/methods/` 的骨架和说明；
  - `dev分支` 说明改成 worktree 开发空间，外部基线写成「非 git 项目兼容」；
  - 示例批次目录换成一份 `批次.json` 示例；
  - 占位符没替换时，`loop 开工` 应该报方法错误，而不是空跑通过。
- `README.md`、`项目文档/运行与维护.md` 的「流水线」「启动」「准备」相关段落改成新做法，具体细节指向工具清单，不在两处重复字段表。
- `README-验收标准.md`【块 1】里「起草任务提示词」那一段，补一句「批次参数写进 `批次.json`，不要在批次目录里写门禁或启动脚本」。改了块内容就把版本号从 v5 升到 v6，并让接入测试覆盖新版本。
- 开发 `opencode-go/deepseek-v4.1-flash` / max；独立评审 `openai-codex/gpt-6-astra` / xhigh；不跑 e2e。

## 边界

- 只改本检出的文档、模板和测试。代码只允许为一致性测试导出现有定义；不改变行为。不访问、不修改原工作目录 `/Users/Admin/Desktop/loop`、其他项目、凭据和全局设置。
- 不修改 `AGENTS.md`、`CLAUDE.md`。用户全局的 `~/.claude/CLAUDE.md` 也不改；它需要的改动（「出 pi 提示词」时先读 `工具清单.md`）写进结果，交给协调方处理。
- 不修改 `temp/`；不迁移任何接入项目。
- 不修改 `test/e2e.mjs` 的场景和断言；认为必须修改时写【需要你决定】并停下。
- 测试产物写系统临时目录；完整 Node 测试由 Loop 门禁执行。

最后交付时写【交付完成】，由 Loop 门禁和独立评审接着执行。

## 验收标准

A1. 操作：打开 `工具清单.md`
    预期：`bin/loop` 的每个子命令、`bin/pi-dev`、流水线、接入命令、来源索引、项目方法的环境变量各有一节；`批次.json` 和 `.autoreview.json` 的全部字段都有类型、默认值和作用
A2. 操作：执行一致性测试；再临时往代码里加一个子命令或字段，但不写进清单，执行一次
    预期：第一次通过；第二次失败，并说出缺的是哪一项
A3. 操作：按项目模板接入一个新的临时 git 项目，占位符不替换就执行 `loop 开工`
    预期：报方法错误，说明哪个占位符没替换；不会空跑通过
A4. 操作：阅读项目模板的目录树和「一批从需求到上线」
    预期：批次目录里只有 `批次.json`、提示词引用和结果；没有门禁或启动脚本；开发空间是 worktree；外部基线只出现在兼容说明里
A5. 操作：对一个装着 v5【块 1】的项目执行 `node setup-acceptance.ts <项目>`
    预期：`.autoreview/CONVENTIONS.md` 被整段替换成 v6，新增的那句批次参数说明在里面
A6. 操作：在 README 和运行与维护里查找「流水线」「启动」「准备」
    预期：写的是新做法，字段细节指向工具清单；不再要求每批写启动脚本
