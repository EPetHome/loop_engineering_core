# 流程配方：「e2e」统一改叫「验收」

## 目标

用户定了：「e2e」这个词不再使用，统一叫「验收」。多段批次在全部段完成后跑的那一次，叫「整批验收」。

现在 `批次.json` 的 `e2e` 字段、`pipeline.ts --from e2e`、流水线的提示和返修消息、README 和工具清单里都还写着 e2e。这一段把它们改掉，旧写法继续能用。

完整设计见 `/Users/Admin/Desktop/loop/docs/方案-流程配方.md` 的「七、E. 改名 e2e → 验收」（只读，以本提示词的「已拍板」为准）。上一段（提交与推送）已经在同一分支上提交，不要改它的行为。

## 已拍板

- **`批次.json` 字段**：
  - 新写法：`"acceptance": { "workDir", "criteria", "maxRounds", …验收配置字段直接平铺 }`。验收配置字段就是原来 `e2e.acceptance` 里的那些，和 `.autoreview.json` 的 `acceptance.*` 同名、同类型、同默认值。
  - 旧写法：`"e2e": { …, "acceptance": {…} }` 照样能读，并提示改成新写法。
  - 两种都写：报计划错误，退出码 3。
  - 平铺后不会撞名：验收配置字段里没有 `workDir`、`criteria`、`maxRounds`。
- **命令行**：`pipeline.ts --from 验收`。`--from e2e` 照样接受。
- **文案**：
  - 「整合 e2e」「e2e 收尾」改成「整批验收」。
  - 返修消息的开头「【流水线 e2e 返修 · 第 N 轮】」改成「【整批验收返修 · 第 N 轮】」。
  - 改消息开头时，要同步改识别机器消息的规则（例如 `isLoopMessage`，以及各宿主按开头识别的地方），并且**继续认出旧的开头**。否则这些消息会被当成用户的话，进入标准和授权的解析。
- **不改的内部名字**：
  - 合入队列 JSON 的 `integration`、`integrationEpoch` 字段。
  - 流水线目录里放材料的子目录名。
  - 这些都是内部名字，改了要迁移旧状态，不划算。
- **Loop 自己的场景测试保持原名**：
  - 不改的有：`test/e2e.mjs`、`test/e2e.test.ts`、报告目录 `autoreview-e2e-*`、`AGENTS.md` 里对它们的引用。
  - README 里介绍这个场景测试的那一节，叙述改叫「实操验收」，文件名照原样写。
- **接入手册**：`README-验收标准.md` 的【块 1】里的说法也要改。【块 1】会被复制进接入的项目，要按现有的版本机制处理：如果 `setup-acceptance.ts` 或接入提醒靠版本号认出旧版，就把版本号升一级。
