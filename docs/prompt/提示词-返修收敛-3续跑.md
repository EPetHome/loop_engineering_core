## 一、目标

改完以后：
1. 单元可以声明"第 1 轮只跑门禁和评审，不开发"（`first_round: "review"`）；
2. `loop_guard.py continue` 接手一份没评审过的候选时，自动用这种方式起草，不让开发方把已经改过的问题再改一遍；
3. `continue` 可以指定从第几轮的候选续跑。

## 三、已拍板的规则（不要改）

1. **新单元字段 `first_round`**（v2）：`"develop"`（默认）或 `"review"`。`kind == 'verify'` 的单元写这个字段就拒绝；没有 reviewer 的单元写 `"review"` 也拒绝。
2. **`first_round: "review"` 的执行**：
   - 第 1 轮不调用开发方，候选就是单元输入（与 verify 路径一样冻结），交付记录由程序写入：`{"origin": "program", "kind": "review_first", "input_hash": ...}`；
   - 然后照常跑门禁 → 评审；
   - 全部通过就 `PASSED`；没通过就照常进入返修（第 2 轮由开发方处理评审意见），返修上限、冻结、停滞等规则全部照旧；
   - 本轮 `history` 项里 `developer` 为 `None`。
3. **`continue_plan()` 自动判断**：如果续接单元有候选、没用 `--fresh-unit`，而且这个候选没被评审过（`result['reviewed']` 为假），就把续接单元写成 `first_round: "review"`，并把追加进 `goal` 的文字改成（原文）：
   > 【续接，与上文冲突时以本段为准】上次运行留下 N 个未解决问题；当前代码是第 R 轮候选，开发方已声称处理，但还没有评审。评审逐条核对：已解决的不再列出，仍未解决的重新列为问题。开发方只处理评审本轮列出的问题。

   候选已经评审过的，保持现在的文字（"请先逐条修复"）和 `first_round: "develop"`。
4. **带走哪些问题**：只带 `kind == 'issue'`、状态不是 `RESOLVED`、不是遗留、**状态也不是 `ADVISORY`** 的项。`ADVISORY` 是 1 号新加的建议项状态，你的副本里还没有，按字符串判断即可。
5. **`--from-round N`**：
   - 从续接单元 `result['history']` 里取 `round == N` 那一项的候选，校验后作为新计划的源码；
   - 没有这一轮、或者这一轮没有候选，就报错并列出可选轮次；
   - 和 `--fresh-unit` 互斥；
   - 第 N 轮评审过（这一项有 `review`）：带走的问题用这一项评审后的 `issue_history`，`first_round: "develop"`；
   - 第 N 轮没评审过：带走的问题用这一项本轮开始时的快照，`first_round: "review"`，文字用第 3 条。
   - 新计划 `notes` 开头的续接说明写明"源码来自 X 单元第 N 轮候选"。
6. `continue_plan()` 的返回值加 `first_round` 和 `from_round`（没指定就是 `null`），命令行照常输出。
7. 预览单元行：`first_round` 为 `review` 时显示 `第 1 轮：只跑门禁和评审（不开发）`。

## 六、改造规格

按第三章逐条实现。补充几点：
- 第 1 轮"先评审"的分支和 verify 分支尽量共用代码，但不通过时要走返修，不能走 verify 的"直接停"。
- 评审方上下文里的 `developer_delivery` 为 `None`，确认评审提示词和协议校验在这种情况下没有问题。
- 第 2 轮开始，冻结规则会拿 `history[-2]['candidate']`（也就是单元输入）和当前候选比较，确认可以正常工作。

## 七、设计约束（陷阱）

1. **候选只读**：上一次运行的候选目录是只读的；`continue` 只是把计划的 `source` 指向它，登记时会复制，不要修改它。
2. **`reviewed` 的含义**：`result['reviewed']` 是"最后一个候选是否就是最后被评审的那个"。只有一轮且已评审过、然后停下的情况，它为真，不能误判成"没评审过"。
3. **按轮取候选**：`result['history']` 里每项的 `candidate` 都要用 `verify_candidate()` 校验指纹；被篡改就报错，不能放行。
4. **文字和字段一致**（`AGENTS.md` 硬规则 5）：`goal` 里的续接文字说"先评审"，`first_round` 就必须是 `review`，反过来也一样。
5. **用失败门禁触发返修**（公共规则 3.3）：测试"先评审不通过 → 进入返修"时，用失败门禁让第 1 轮不过，不要构造评审 issue。
