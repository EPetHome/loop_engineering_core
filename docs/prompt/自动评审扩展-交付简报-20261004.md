## 2. 实测发现

1. **`--session-id` 接受什么格式**：接受 `autoreview-rev-<开发会话uuid>`（字母、数字、`.`、`_`、`-`），不需要退回 sha256 UUID。评审会话文件形如 `~/.pi/agent/sessions/<项目slug>/<时间戳>_autoreview-rev-<uuid>.jsonl`；同一个 id 复用同一文件与上下文（R5 里直接补跑 2 次验证）。
2. **`review-prompt.md` 的路径怎么解析**：`dirname(fileURLToPath(import.meta.url))`，jiti 加载下可用（先用临时扩展验证，再在真实评审里生效）。
3. **RPC 模式下 `ui.notify` 和命令的表现**：`ctx.ui.notify` / `setStatus` 以 fire-and-forget 的 `extension_ui_request` 记录出现在 stdout（`method: notify` 带 `message`/`notifyType`；`method: setStatus` 带 `statusKey`/`statusText`），客户端不需要回复。扩展命令用 RPC `prompt` 发 `/review-status`、`/review-off` 会立即执行、不触发模型轮次。实测输出：
   `自动评审：开启\n状态：空闲\n评审 0 次，返修 0 次\n评审会话：autoreview-rev-<uuid>\n总结：/Users/Admin/.pi-autoreview/<项目>/<会话>.md`
4. **Astra 一次评审的耗时**：玩具仓库单轮 **17 秒**（xhigh，结论「通过」）。
5. **标记遵守情况**：约定确实追加进了开发方系统提示（在开发会话系统消息里能搜到全文），但 `opencode-go/deepseek-v4.1-flash` 六个场景首次交付都没写【交付完成】；联调驱动加了 45 秒无标记兜底 nudge（测试工具行为，不是产品行为），每场景各用 1 次。产品本身不 nudge：没有标记就不评审；刚收过返修消息却没写标记时暂停。
6. **真实评审运行测试的副产物**：R5 里评审方跑 `python3 test_calc.py`，在开发方已清理 `__pycache__/` 后重新生成它，指纹不一致 → 按规格暂停「评审改动了工作区」，总结列出该文件。这是规格要求的保护行为，不是缺陷；介意的话给项目加 `.gitignore`。
7. **Node 单测**：Node 22.23 直接跑 `.ts`（只用可擦除语法、导入带 `.ts` 后缀），`node --test` 正常。

## 4. 用法

```bash
cd <你的项目>
pi -e /Users/Admin/Desktop/loop/autoreview.ts
```

带 flag 的完整示例：

```bash
pi -e /Users/Admin/Desktop/loop/autoreview.ts \
   --autoreview-max-repairs 3 \
   --autoreview-reviewer-model openai-codex/gpt-6-astra \
   --autoreview-reviewer-thinking xhigh
```

开发方最后一行写【交付完成】自动评审；写【需要你决定】只通知你；返修时开发方逐条写「第 N 条：已修 / 异议：理由」。四个命令：`/review`、`/review-off`、`/review-on`、`/review-status`。总结在 `~/.pi-autoreview/<项目目录名>/<开发会话id>.md`。
