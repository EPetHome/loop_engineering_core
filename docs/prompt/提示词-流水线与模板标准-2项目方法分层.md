# 流水线与模板标准 · 第 2 段：项目方法分层、越界检查、权限检查

## 目标

接入项目的门禁脚本现在每批重写一遍。以 Promate 为例，两批的 `gate.py` 去掉批次名后对比，差异 250 行，原文件 171 行。原因是每份脚本里混着三类东西：

- loop 该管的：失败分类、越界检查、开工依据；
- 项目固定的：怎么测；
- 本批的参数：范围、测试选择。

本段把 loop 该管的部分收进引擎，并把开工依据和本批参数通过环境变量交给项目方法。这样项目方法只写一份，每批只改 `批次.json`。

设计依据是 `docs/方案-流水线与项目模板标准.md` 的第 4.2 节。第 1 段已经在本检出里实现了 `bin/loop` 和 `批次.json`，先读 `docs/batches/流水线与模板标准/结果.md` 的「第 1 段」一节，在它的基础上做。唯一结果写入同一文件的「第 2 段」一节，逐条列出 A1–A6 的实现、证据和未验证的内容。

当前工作目录是本批唯一授权的隔离检出。开始时先用 read 读 AGENTS.md、方案和第 1 段结果，用 bash 执行 `pwd`，然后自主推进实现和受影响的定向自检，不要每一步都停下等批准。

## 已拍板

- loop 执行项目方法时（准备检查、门禁、自动验收的启动和重置、验收命令），多传三个环境变量。单段会话和流水线都要传。
  - `AUTOREVIEW_BASE_REV`：本段开工依据，用会话开始时已经记录的 `state.baseline`；
  - `AUTOREVIEW_BATCH_FILE`：`批次.json` 的绝对路径；没有批次文件时不设置；
  - `AUTOREVIEW_STAGE`：段名；单段时取 `批次.json` 里唯一那一段的名字。
- `loop 启动` 把 `AUTOREVIEW_BATCH_FILE` 和 `AUTOREVIEW_STAGE` 交给 Pi 会话，扩展从会话环境里读取。
- 越界检查：`批次.json` 的段可以写 `scope: { allow: [...], deny: [...] }`，写的是相对项目根的路径前缀。门禁之前，loop 对比开工依据以来的改动文件（包括未跟踪文件），出现不在 `allow` 里或落在 `deny` 里的文件，就按产品失败打回原会话。返修消息列出越界文件，计入业务返修次数，复用现有的门禁返修路径。没写 `scope` 时不检查。
- loop 不解释棘轮模式、测试选择这类项目参数，只通过 `AUTOREVIEW_BATCH_FILE` 交给项目方法自己读。
- 权限自动执行检查放进启动入口（`bin/pi-dev`，流水线也经过它）。检查项目的 Pi 权限扩展配置能让开发会话不经询问执行 edit、write 和 bash，检查不通过就报错退出，不改用户的权限配置。这个检查由第 1 段的方法指纹控制：指纹不变就跳过，变了就执行一次。可以只读参考 `/Users/Admin/Desktop/Promate/coding/docs/新闻模块解耦-20261024/自动执行检查.mjs` 的做法，不要修改它。
- `.autoreview.json` 新增的字段（`release`、`workspaces`、`localFiles`、`methods`）和 `批次.json` 的 `scope` 都要做解析校验，报错信息说明字段名和原因，写法和 `config.ts`、`preparation.ts` 现有的一致。

## 验收标准

A1. 操作：配置一个把三个环境变量写进运行目录的门禁命令，分别在单段会话和两段流水线里交付一次
    预期：门禁拿到的 `AUTOREVIEW_BASE_REV` 等于本段开工依据，`AUTOREVIEW_BATCH_FILE` 是 `批次.json` 的绝对路径，`AUTOREVIEW_STAGE` 是本段段名
A2. 操作：同样检查准备检查、自动验收的启动和重置命令、验收命令拿到的环境变量
    预期：这几个命令都拿到同样的三个变量
A3. 操作：段配置 `scope.allow: ["src/"]`，开发方改了 `src/a.ts`，又新建了 `docs/x.md`
    预期：门禁没有执行；原会话收到越界返修，消息里列出 `docs/x.md`；返修次数加 1，会话不暂停
A4. 操作：段配置 `scope.deny: ["src/secret/"]`，开发方改了 `src/secret/k.ts`；另一次没写 `scope`
    预期：前者以越界打回；后者不做越界检查，行为和现在一样
A5. 操作：项目的权限配置不能自动执行 bash 时执行 `loop 启动`；改好后再执行一次；指纹不变时第三次执行
    预期：第一次报错退出，说明原因，权限配置没被修改；第二次通过；第三次跳过检查
A6. 操作：`.autoreview.json` 写错 `methods.paths`（不是数组），或 `批次.json` 写错 `scope`
    预期：报错里给出字段名和原因，不启动会话
