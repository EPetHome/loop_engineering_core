# 准备批S：共用验收隔离方法

## 目标

提供一份Loop仓库内可复用的隔离执行工具，后续多段验收通过它启动内层样本，不再把演示批次写进真实用户的流水线、队列、事件和交付记录。每轮创建独立环境，正常、失败和取消都按身份收尾；同一份方法供后续批次使用，不共享上轮活数据。

来源只读：`/Users/Admin/Desktop/loop/issues/【bug】验收演示数据写入真实状态目录.md`的A1—A5，以及总方案的准备批S与共用隔离条件。任务只修验收隔离，不修⓪配置指纹、失败分类、预算或批次终态。

## 已确定的要求

- 主脚本放 `acceptance-tools/isolated-loop.mjs`，操作说明放 `acceptance-tools/isolated-loop.md`，必要自检放 `test/acceptance-isolation.test.ts`。复用现有资源归属与执行器能力，不新增依赖或环境平台。
- 私有HOME、队列、资源、项目记录、Pi配置、临时目录及PA配置在任何内层进程启动前生效；不继承真实模型凭据或外层批次身份。后台入口会清除TMPDIR时，TMP/TEMP等备用临时目录仍须留在本轮根内。只给子进程传环境，不修改宿主全局设置。
- PA配置必须真实存在且明确关闭本地通知。HOME隔离不能替代显式输出路径检查；声明的越界路径在派发前拒绝。
- 内层样本允许读候选程序与已安装工具，写入限定本轮私有根；正式证据目录是调用者明确给出的输出例外，只写本轮唯一日志/报告，不覆盖已有材料。
- 这是受控验收方法，不宣称仅靠环境变量即可抵御任意恶意程序的绝对路径写入。验收中的越界反例只指向独立外层临时哨兵，不拿真实用户目录做探针。
- 原始命令输出、路径、退出原因和归属记录先保存，再清理自己的资源。主命令退出不等于后台消费者退出；无法确认释放时非零结束并保留现场，不根据名称、年龄或PID猜测清理。
- 本批走独立评审、门禁、本批自动验收和原有必需实操验收。验收由独立模型操作，不由开发方自报、单测总数或工具自己打印PASS代替。

## 对外操作约定

为保证后续指南有确定入口，本次实现以下最小CLI；这些是待实现接口，不是声称当前已有能力：

```text
node acceptance-tools/isolated-loop.mjs --target <只读候选Loop根> --evidence-dir <明确的外层证据目录> --label A1 [--write-path <路径>]... [--timeout-sec N] -- <命令及参数>
```

- `--help`只打印参数说明，不创建环境或启动子进程。参数解析用已有能力或标准库。
- 每次在调用方提供的临时父目录（`TMPDIR`/标准库tmpdir）下新建私有根，尊重独立外层的父目录，不硬编码另一个系统路径。`--write-path`用于声明额外写入目标，相对路径按新私有根解析，绝对路径及符号链接按真实归属核对。未落在私有根内的声明在启动命令前拒绝，`--evidence-dir`是唯一显式外部输出例外。
- 子命令cwd为新私有根，环境包含 `LOOP_ISOLATION_ROOT`、只读的 `LOOP_CANDIDATE_ROOT`，以及所有私有状态根；清除外层批次/会话和启动身份。新增内层身份由受控场景按其私有路径声明。
- 超时有界，外部取消要传递到本轮进程；原始stdout/stderr向调用方输出并存档。成功或失败都给出可追溯报告。
- 最后输出 `ISOLATION_REPORT=<本轮JSON报告绝对路径>`。报告至少有 `root`、`paths`（home、queues、resources、projects、agent、paEvents）、`commandExitCode`、`processesReleased`、`rootReleased`、`stdoutLog`、`stderrLog`；失败或保留现场时 `reason` 非空。这些字段描述实际结果，不能先写成功再执行收尾。
- 命令失败保持非零；释放未确认也非零。正常结束且已确认释放时清理本轮私有根；失败场景可按规则保留，报告必须说明归属和原因，不能伪称已清理。

## 边界与步骤

工作目录 `/Users/Admin/Desktop/loop-共用验收隔离`，分支 `feat/acceptance-isolation`。只改本工作区上述三个文件和 `docs/batches/共用验收隔离/结果.md`；不修改运行版、全局配置、既有规则、`test/e2e.mjs`、其他项目或历史演示登记。

先读 `resources.ts`、`procs.ts`、`hosts/review-hook.ts` 中受管执行与释放入口，以及 `events.ts`、`project-context.ts`、`ledger.ts`、`config.ts` 的状态路径。参考现有临时夹具的做法，但不导入会注册node:test钩子或改全局环境的整个测试夹具作为产品运行入口。

S的独立验收外层由协调方提供的固定bootstrap工具负责，位于运行版 `.autoreview/methods/acceptance-outer.mjs`，不在本批可修改范围。它只保护受控样本和兜底收尾，不替代本工具应完成的隔离与释放；外层替候选清理掉进程不能算候选通过。

开发后先跑相称的定向自检；完整门禁、本批自动验收和原有required实操命令由Loop执行，不手工重复全套。保留auto权限与deny，不改成逐工具确认，不自行提交、合入、推送或关闭原问题单。

唯一结果 `docs/batches/共用验收隔离/结果.md`：逐条列出独立操作、原始证据、候选版本、判定、未验证项与资源归属；记录新工具实际命令和后续复用方式。完成开发自检后按约定写【交付完成】，由Loop继续检查，不能把该标记当成验收已通过。

## 验收标准

A1. 操作：用候选工具运行受控内层Loop开工、启动及状态落盘场景。
预期：真实pipeline、queue、event和其他样本输出落在本轮私有根；HOME及各状态根均为本轮值，正式证据保留，真实状态不新增样本身份。

A2. 操作：分别声明父目录、绝对路径和符号链接指向的外层临时哨兵作为写入目标。
预期：派发命令前拒绝，指出具体路径；哨兵内容未改，命令未执行，不以字符串前缀冒充路径归属。

A3. 操作：并行运行两个同名场景，再连续运行一轮。
预期：各有不同私有根和身份，真实写入互不覆盖；后一次不读取或沿用前一轮样本状态。

A4. 操作：分别让子命令正常、失败、超时和收到取消；包含脱离原进程组的独立消费者。
预期：候选返回前确认本轮消费者已停止，失败/取消原因准确；原始证据保留、资源按归属处理。必须在外层兜底收尾之前观察，不能把bootstrap的清理算成本工具成功。

A5. 操作：内层触发Loop事件及通知，并让后台消费者记录实际环境。
预期：事件只写私有PA目录、本地通知明确关闭，后台仍使用本轮私有状态；真实用户配置与旧记录不变。
