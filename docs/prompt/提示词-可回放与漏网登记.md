# 每轮评审留下可复原的快照，事后发现的问题能登记成回放案例

## 目标

评测基线（`/Users/Admin/Desktop/loop/eval/报告/基线-20261027.md`，只读）里，能拿来回放的漏网缺陷只有 2 个。原因有两个：历史快照只记了未跟踪文件的路径和哈希，没存内容；也对不上当时跑的是哪一版 Loop。所以大部分案例复原不了。以后改评审规则前，要靠回放比较新旧两版的效果（`/Users/Admin/Desktop/loop/docs/方案-开发测试闭环.md` 第 6 节，批 6 的前置），因此先补上这两件事：

1. **可复原的快照**：每轮评审保存这一轮看到的完整代码，包括已跟踪的改动和未跟踪文件的内容（被忽略的文件不存），并记下当时运行的 Loop 提交号。
2. **漏网登记**：`bin/loop` 新增一个子命令。事后发现某个已完成的会话漏了问题时，指定项目、会话、轮次（不写时取最后一轮）、问题描述和发现方式。程序随后做两件事：
   - 在交付总表里追加一段「漏网」记录；
   - 在本机生成一份回放案例草稿，字段对齐 `/Users/Admin/Desktop/loop/eval/README.md`「案例」一节列出的必填字段，并指向那一轮的快照。

## 已拍板

- 快照存在本机数据目录，不写进项目。快照算作保留类，`loop 清理` 不删。
- 单个未跟踪文件超过 256KB 时，只记路径和哈希，不存内容，并在快照记录里标明这一项缺内容。
- 案例草稿只写到本机，不自动放进 `eval/cases/`；要由用户或 Codex 核对后再收进去。
- 登记不改原会话的状态和总结，也不重新评审。
- 交付总表沿用现有写法：一段一次写完，只追加。

## 边界

- 代码主要涉及：保存评审快照的地方（`review.ts`、`autoreview.ts`、`hosts/hook.ts`，现在的 `baselineUntrackedDetails` 只记哈希）、`materials.ts`（保留类）、交付总表的写入代码、`loop.ts`（新子命令）。测试放在 `test/`，数据全部在系统临时目录里造。用法同步到 `README.md` 和 `工具清单.md` 的 `bin/loop` 一节。
- `eval/` 只读参考，不修改；不改 `review-prompt.md`，不改 `test/e2e.mjs` 的场景和断言，不改 `iusses/`、`temp/`。
- 不写真实的 `~/.pi-autoreview`，不提交，不推送。

A1. 操作：造一个临时 git 项目，里面有已跟踪的改动、未跟踪文件和被 `.gitignore` 忽略的文件，跑一轮评审。
    预期：只用本机保存的快照，就能还原出这一轮的完整代码：已跟踪内容和每个未跟踪文件的哈希都一致；被忽略的文件不在快照里；记录里有当时的 Loop 提交号。
A2. 操作：在未跟踪文件里放一个超过 256KB 的文件，再跑一轮。
    预期：这个文件只记了路径和哈希，没有存内容；快照记录里标明这一项缺内容。

    预期：交付总表末尾多出一段漏网记录，写明项目、会话、轮次和问题描述；生成的案例草稿包含 `eval/README.md` 列出的全部必填字段，无法确定的字段写 `null`。

    预期：复原结果与 A1 那一轮的代码一致；整个过程不调用任何模型。

    预期：快照不在删除名单里。
