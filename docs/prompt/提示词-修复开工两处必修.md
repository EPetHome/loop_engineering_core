# 修复开工搬运的两处必修，并给 Loop 自身配门禁

## 目标

评测回放（`eval/runs/2026-10-27/C002/review.md`）在当前代码里发现了两条必修，都出在 `loop 开工` 搬运批次文档的链路上。这条链路每个批次都要走。另外，Loop 主目录的 `.autoreview.json` 是 `{}`，自己开发自己时没有门禁。背景见 `docs/方案-开发测试闭环.md` 第 6 节批 1。

1. **覆盖本地文件**（`loop.ts:317-327`）：开发空间里有被 git 忽略、又未跟踪的同名文件时，`checkClean` 看不到它，`copyBatchDocs → writeDocSafely` 会直接用 `renameSync` 覆盖。之后即使 `git add` 失败，被覆盖的内容也无法恢复。
2. **相对路径失效**（`batch-refs.ts:30-40`、`pipeline.ts:176`）：搬运批次文件时，只改写了提示词和验收标准的引用，没有处理相对路径写的 `stages.<段>.cwd`。搬运后它按新的批次目录解析，指向一个不存在的目录，导致开工成功但启动失败。
3. **配门禁**：在 `.autoreview.json` 中设置 `release` 为 `dev`（主目录实际运行的就是 dev），并配置 `gate`，执行本仓库单测。

## 已拍板

- 第 1 条：写入前，凡目标位置已有未跟踪内容（包括被忽略的），一律停下并列出路径，不覆盖。不做"备份后覆盖"。
- 第 2 条：搬运后，显式写出的 `cwd` 仍指向原来那个目录。同时检查其他依赖批次目录来解析的路径字段，有同类问题的一并修复。
- 门禁命令：`PATH="/Users/Admin/.hermes/node/bin:$PATH" node --test test/*.test.ts`；`timeoutMin` 按实际耗时留出余量，不超过 20。
- 两条修复都要补测试，测试要能在旧代码上复现失败：被忽略的同名文件不被覆盖；非同级工作区配合相对 `cwd` 时能正确启动。

## 边界

- 只改与这两条相关的代码和测试，以及 `.autoreview.json`。不改 `review-prompt.md`、`test/e2e.mjs` 的场景和断言、`eval/`、`temp/`，也不改其他文档。如果用法说明确实需要改，只改 `工具清单.md` 或 README 里对应的那一句。
- 不提交，不推送。
- 评审时提到的 `test/loop.test.ts` 那条小问题（直接断言开工后的越界检查），可以顺手补；补不了也不阻断。
