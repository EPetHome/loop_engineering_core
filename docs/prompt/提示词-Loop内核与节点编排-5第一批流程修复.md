## 已拍板与必须实现

### 1. 默认可见、可交互的 Pi 开发窗口

正常启动 Pi 新开发卡时，每个被启动的开发任务有独立 Pi 终端窗口，可看过程、输入补充要求。多任务不能默认加 `-p`；只有明确选择后台运行才不弹窗。只评审卡不能增加开发会话。

复用主目录现有 `--launcher terminal`/开窗/原会话恢复实现，但将 Pi 开发默认行为改为可见。`--json` 等输出选项与显式后台的关系按既有调用者核对，不能因机器读取输出就偷偷改变用户要求的前后台；不支持的组合明确报错。保留显式 background，续跑保持原任务、目录、会话、计数；先核对活动身份防重复派工，部分开窗失败明确列出，不静默转后台。

当前复用实现通过 osascript 调 macOS Terminal。本批落实当前 macOS 环境，其他平台清楚诊断/保留显式后台，不顺带引入跨平台终端框架。保留原 auto 与明确 deny，不改全局/项目权限模式。

### 2. gate 提示不再刷屏

旧 gate 继续忽略、不执行、不校验内容。配置解析函数不打印弃用提示；如保留提醒，只由批次启动入口统一显示，同一运行最多一次。子任务、轮询、状态查询、续跑不重复。保留卡和配置输入变化保护，不删用户配置、不恢复旧 gate 测试来解决刷屏。

### 3. 持续显示真实流程

`kernel-pi.ts` 复用同一内核账本及查询来源，用 Pi 现有状态栏/必要小部件持续显示当前任务、节点、轮次、排队、返修、暂停原因、完成结果。评审开始时就显示，外部节点 worker 的变化同步到原窗口，不能只在 show/手动查询/整段 Promise 结束时弹一次通知。

区分本任务与整批；排队不显示执行中，一个任务暂停不把其他活动任务写成全批暂停。空闲会话、`stopped=false`、窗口或进程存活不构成正在执行。轮询/订阅有明确生命周期，关闭/重载后停止，通知去重；不另造第二套状态机。程序测试必须记录并断言实际 setStatus/notify 变化，不能用空 UI 方法宣称可见。

### 4. 交付、返修、续跑自动衔接

核对 `kernel-pi.ts` 和 `hosts/kernel-hook.ts` 的共同早退条件：不能以“无末行标记且无脏文件”直接认定无需推进。根据当前候选、交付上下文、原会话返修信封和必需节点有效结果，决定评审、接续测试或等待批次验收。

覆盖完成标记位于回复开头；候选已由程序提交而目录干净；无新增改动但仍欠检查；原会话返修和停止后续跑。只重做真正失效的检查，不重复派工、不清零次数；不能把正文任意出现标记当授权，普通讨论、需要用户决定、真实停止与补充要求仍有明确边界。不能安全推进时显示具体原因和可执行的下一步，不静默闲置。

尽量将共同判断放在已有共享接缝，两宿主行为一致。**不改旧单会话 autoreview.ts 的完成/跳过判断**；它正承担本轮外层评审。共享函数若确需改变，要保留旧调用语义并覆盖相关回归，不能为新卡误触发普通会话。

### 5. 构建/缓存与检查保护兼容

同时核对 `test-node.ts` 实际执行目录、`kernel.ts/executeNode` 的工作区/索引监听、`kernel-workspace.ts/workspaceGuard/checkInputs` 的前后比对，修复 Node 构建输出与 Git 已忽略的 Python `__pycache__/*.pyc` 导致中断的问题。

优先复用已有 `includeIgnored` 接缝做最小修复，但**Git 忽略规则不等于产物授权**。必须明确识别本次受控构建/缓存写入，登记产物路径与证据，同时继续保护 Git 跟踪文件、暂存区、非忽略新增文件、真实执行输入、localFiles、卡、配置、标准和授权。仅传 false、关闭 watcher、忽略全部目录事件或全部 ignored 文件都不算修复；瞬时写入/写回、链接与路径边界不能被绕过。

如果原地执行无法可靠区分受控产物与输入，采用能实际运行卡上原命令的最小隔离方案，接入候选/输入/证据/消费者与目录释放，不停留在提案，也不额外建依赖安装体系。常规选择由你读代码和反例后完成，不反复请用户选择算法。

保留第四步项目互斥和释放语义，复用主目录 `GIT_OPTIONAL_LOCKS=0`，兼顾共享评审执行器的释放回执。不得通过删构建、改成“无测试”、删断言或放宽用户标准制造通过。历史 Word/PA 中断记录只证明出现过问题，具体触发路径未留证据，不能声称已复现其唯一原因。

### 6. 中断后的处理与停点

追踪 `executeNode → finishAttempt → advanceManaged → kernelPi`，区分原始取消原因和“旧结果无效”的结论。真实候选/输入变化、用户停止、未知消费者继续拒绝旧结果，但显示哪个任务/节点停下、原因及可执行下一步。

可恢复环境问题只按既有额度与授权处理；停止或过期结果不能为了自动接续而重放动作，不清零计数、不把环境问题算产品返修。资源释放未知单列，不冒称通过或完成。
