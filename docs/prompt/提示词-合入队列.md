# 合入队列：在最新发布分支上先测后合

## 目标

`loop 合入` 现在只合并、不测试。几个批次各自在自己的分支上测过，合到一起以后出了问题没人发现；合入时用的是哪个版本也没有固定下来，事后发现问题时复原不了。背景见 `/Users/Admin/Desktop/loop/docs/方案-开发测试闭环.md` 第 3 节第 3、6 条，以及第 5 节的「合入队列」部分（只读）。

做一个本机串行的合入队列，每个仓库一条：

```
批次完成 → 自动进队 → 轮到它：固定测试工作区重置到发布分支最新提交 → 合入批次分支
  ├ 有冲突 → 测试工作区恢复干净 → 退回该批次的开发会话：合进最新发布分支、解决冲突，重走门禁和评审 → 完成后回到队尾
  └ 没冲突 → 在合并结果上跑项目门禁
       ├ 不通过 → 带上门禁输出退回该批次 → 修完回到队尾
       └ 通过 → 通知用户「可合入」，等用户执行 loop 合入 → 处理下一个
```

## 已拍板

- 批次完成后自动进队：单段批次以开发会话完成为准；多段批次以流水线全部段完成、并且 e2e 通过为准。
- 每个仓库同一时间只测一个批次。测试工作区固定一个，不能是运行版目录，也不能是任何批次的开发空间。
- 测试通过后，必须等用户执行 `loop 合入` 才更新发布分支，不自动合入。
- 合入时要核对两点：发布分支仍是测试时的那个提交；合入结果就是测过的那个结果。发布分支已经变了，就不合入，改为重新测试。
- 冲突和测试失败都退回该批次原来的开发会话；会话已经关了，就按现有方式恢复同一个会话，不新开。多段批次按冲突或失败文件的归属找到对应的段；找不到时退回最后一段，并在消息里写明原因。
- 队列只跑程序检查（项目门禁），不在队列里重跑 LLM 验收。
- 队列由程序执行，不依赖 Claude 或任何会话在场。运行中进程被杀或机器重启，下次触发时从队列记录恢复，既不重复合入，也不丢批次。
- 只在本地运行：不推送，不用 GitHub Actions。
- 只对用 `loop 开工` 开出的 git 批次生效。不是 git 仓库的项目（例如 Promate 的开发目录），行为保持不变。

## 边界

- 代码主要涉及：`loop.ts`（进队、`状态` 里显示队列、`合入` 时的核对）；`pipeline.ts`、`autoreview.ts`、`hosts/hook.ts`（完成时进队）。退回沿用流水线现有的收件箱和恢复会话的方式；单段批次没有收件箱的，补上同样的通道。测试放在 `test/`，一律用系统临时目录里的 git 仓库，配替身门禁和替身开发会话。用法同步到 `README.md` 的「开工、启动、状态与合入」一节和 `工具清单.md` 的 `bin/loop` 一节。
- 整个过程只改测试工作区和队列记录。运行版只在用户执行 `loop 合入` 时才改；批次开发空间只由被退回的那个开发会话改。
- 不改 `review-prompt.md`，不改 `test/e2e.mjs` 的场景和断言，不改 `eval/`、`iusses/`、`temp/`。
- 不对真实仓库跑队列，不提交，不推送。

## 验收标准

A1. 操作：在临时仓库里让两个批次先后完成，然后执行 `loop 状态`。
    预期：两个批次都自动进了队，一次只测一个，按完成的先后顺序；`loop 状态` 能看到每个批次在队列里的位置和测试结果。
A2. 操作：批次分支与最新发布分支没有冲突，门禁替身返回通过。
    预期：用户收到「可合入」通知；用户执行合入之前，发布分支保持不变。
A3. 操作：A2 通过后执行 `loop 合入`。
    预期：发布分支得到的就是测试时的合并结果，文件内容一致。
A4. 操作：A2 通过后，先往发布分支合入另一个提交，再对原批次执行 `loop 合入`。
    预期：不合入，提示发布分支已经变化，并自动重新测试。
A5. 操作：让批次分支与发布分支在同一个文件上冲突。
    预期：测试工作区恢复干净；该批次的开发会话收到退回消息，消息里列出冲突文件，要求合进最新发布分支并解决冲突；处理完成后，这个批次重新排到队尾。
A6. 操作：让门禁替身在合并结果上失败。
    预期：门禁输出随退回消息一起发给该批次，不发「可合入」通知。
A7. 操作：测试进行到一半时杀掉队列进程，然后再次触发。
    预期：从队列记录恢复，不重复合入，也不丢失批次。
A8. 操作：在 A1 到 A7 的整个过程里，比较运行版目录和批次开发空间前后的状态。
    预期：除了 A3 里用户执行的合入，以及 A5、A6 里被退回会话自己的修改，没有其他改动。
A9. 操作：执行 `PATH="/Users/Admin/.hermes/node/bin:$PATH" node --test test/*.test.ts`。
    预期：全部通过。
