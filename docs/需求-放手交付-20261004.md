# 需求：放手交付——用户只做两个决定，其余交给程序和订阅模型

> 提出：2026-10-04　·　状态：待排期（排在「返修收敛」这批提交之后）　·　读者：用户、负责准备和实现的 AI（Codex / pi）

## 一、要解决的问题

Loop 的本意是：用户定目标，其余由 AI 准备、Loop 执行。用户只做决策。

2026-10-04 修 Loop 自身问题时，实际流程却变成了这样：

```
用户 ─启动→ pi 开发 ─简报→ 用户「完成了」→ Claude 写派单 → 用户 ─启动→ Astra 复核 → …
```

| 用户的动作 | 次数 | 是否决策 |
|---|---|---|
| 复制命令、启动 pi 或 Astra | 10 | 否，是搬运 |
| 回来说「完成了」 | 7 | 否，是传话 |
| 选范围、拍板 | 3 | 是 |

这一套「开发 → 复核 → 返修 → 复查」就是**手工版的 Loop**：状态机由用户来当，传话由用户和 Claude 来做。Claude 按用量计费，用户出于成本考虑，不希望 Claude 留在执行链上。

## 二、目标

用户只做两个高杠杆的决定，其余环节都交给零 token 的程序和订阅模型：

```
用户定目标
  → 准备：Codex（订阅）写验收脚本和 plan.json，登记、封存
  → 【决定 1】用户看预览，确认验收口径，输入 yes
  → Loop 自动完成：开发 → 门禁 → 评审 → 返修 → 判停 → 总收尾
  → 结果页开头是一张决策卡
  → 【决定 2】用户做业务验收，并处理建议项和遗留发现
```

| 环节 | 由谁负责 | 成本 |
|---|---|---|
| 定目标、确认口径、业务验收 | 用户 | — |
| 准备、起草续跑计划 | Codex（prep 目录，装有 loop-guard 插件） | 订阅 |
| 调度、判定、记账、总收尾 | Loop 程序 | 零 |
| 开发 / 评审 | pi + gpt-6.1-sol / gpt-6-astra | 订阅 |
| 设计讨论、引擎大改的方案 | Claude（只在需要时用） | 按用量 |

两个决定**必须留给用户**，不是因为技术上做不到，而是没人能替：

- 验收口径错了，后面的自动化会很高效地做出错误的东西；
- 「达标」只代表符合口径，不代表就是用户想要的。

## 三、需求清单

| # | 需求 | 验收标准 |
|---|---|---|
| F1 | **决策卡**：result.md 开头固定一节，不超过 12 行，内容包括：结论（达标 / 未达标 / 推不动）、需要用户定的事（建议项和遗留发现的条数，以及去哪里看）、默认推荐、不处理会怎样、成本合计 | 三种停止结果各生成一次，决策卡都在第一屏；数据缺失时写「未知」 |
| F2 | **pi 派单和复核派单统一加决策卡**：简报和复核结论的末尾都加同样格式的决策卡，供 Loop 外的工作流使用 | 写进派单模板（公共规则）；下一份派单开始执行 |
| F3 | **准备交给 Codex**：在 prep 目录里由 Codex 完成 begin → patch → check → seal，并把启动命令交给用户；Claude 不参与 | 用一个真实小任务走通，记录 Codex 的问题点 |
| F4 | **用 Loop 开发 Loop 自己（自举）**：把 loop 仓库的副本登记成项目，门禁用 `verify_release`（套上 macOS 短临时目录包装器），评审用 Astra，结果是候选副本；用户验收后再合回 dev | 用一个小改动试点（建议从附录 B 的「行号读取提示」开始）；从准备到结果全程用户只操作两次 |
| F5 | **续跑起草交给 Codex**：未达标时，Codex 执行 `continue` 起草计划，用户只确认 | 同 F3 |

## 四、前提与风险（开工前先验证）

| # | 风险 | 处理 |
|---|---|---|
| P1 | 成员提示词里写着「不得修改规则、旧交接、引擎」，而自举时成员要改的正是引擎代码的**副本** | 说明文字不能和 plan 字段矛盾（AGENTS.md 硬规则 5）。notes 里写清楚「改的是副本，运行中的引擎不受影响」；必要时调整成员提示词的措辞 |
| P2 | 开发方不能执行任意命令；pi-lens、类型检查这类检查只能写成门禁 | 自举的 plan 把 `verify_release` 拆成快速门禁（040 套件）和正式全量门禁 |
| P3 | 自举运行期间不能改动 dev 树里的 `engine/` 等目录（完整性检查会把它当成篡改） | 运行期间 dev 树冻结；候选合回 dev 由用户在验收后进行 |
| P4 | 全量门禁约 2.5 分钟，时限和自测额度要配够 | 按「返修收敛」的时间预留规则配置；预览会提示时限是否够用 |
| P5 | Codex 做准备的质量未知 | F3 的试点就是用来验证这一点；不行就退回 Claude 准备，但只做一次，不进执行链 |

## 五、明确不做

- 让 Claude 或任何模型握有启动权，或者让它判定「通过」
- 去掉启动前的确认步骤
- 自动合并回原项目
