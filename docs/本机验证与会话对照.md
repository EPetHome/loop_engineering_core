## 2. 真实对照前提（用户先确认）

- 使用一次已批准的完整任务规则，源为相同、保持不变的非生产项目；固定目标/标准/门禁/角色/模型/思考级别/工具/权限扩展/预算。任务最好自然需要业务返修，但**不人为弱化标准、伪造失败或强制真实模型多花钱**。没有发生业务返修则记录“未触发复用，收益不可比”。
- 开发 agent 必须是本交付 `adapters/pi_member.py` 的直接本地 command/stdout；内置 pi/codex 和任意 wrapper 不支持复用，会明确拒绝。评审始终新会话，工具按原已批准规则配置，不为对照自动放宽。
- 用户自行通过本机已有方法核对 Pi 0.87.1 版本/参数、账号额度、实际模型权限与权限扩展。不要上传凭据或用 doctor 当账号验证；不要升级依赖、改全局 Pi 配置或关闭权限插件来绕过失败。`--offline` 不阻止已授权的模型请求，两种正式启动都可能计费。
- reuse 只支持 macOS 可执行的 `/usr/bin/sandbox-exec`，每次会实质探测旧路径拒写/当前开发目录可写；平台/权限不支持则拒绝策略，不能悄悄当成受保护的复用。用户先看失败原因，不无限 retry。
- 两种规则只允许 developer_session 不同；因此整体 rule_hash 必然不同，但业务字段与预算必须相等，unit_input_hash 必须相同。新 run 的 session 不继承对照另一臂或其他运行；顺序/缓存/供应商波动是混杂因素，不能由一次运行推断节省。

## 3. 一次性生成完整两种规则（不调用模型）

用户在上述组合目录或解压后的同结构目录，准备自己的 `approved-task.json`。该文件中开发 argv 已配置交付内适配器、实际已确认的模型/思考/工具，并保留相同评审配置。以下脚本只规范化并复制该已批准规则，**不增加标准或预算**；路径换成用户实际位置。数据与计划放在 source 之外。

```bash
cd /absolute/path/to/composed-project
export PY=/opt/homebrew/bin/python3.12
export BASE_PLAN=/absolute/path/to/approved-task.json
export COMPARE_DIR=/absolute/path/outside-source/session-comparison-01
# 仅由用户确认后设置本机真实 CLI；两臂完全相同。
export LOOP_PI_BIN=/Users/Admin/.local/bin/pi

"$PY" - "$BASE_PLAN" "$COMPARE_DIR" <<'PY'
import copy, json, sys
from pathlib import Path
sys.path.insert(0, str(Path.cwd() / 'engine'))
from loop_engineering.rules import load_rules
from loop_engineering.sessions import supports_reuse
base, out = Path(sys.argv[1]), Path(sys.argv[2]).expanduser().resolve()
rules = load_rules(base)
assert not out.exists(), '对照目录必须新建，保留以前的结果'
assert not out.is_relative_to(Path(rules['source'])), '对照目录不能在 source 内'
for u in rules['units']:
    a = rules['agents'][u['developer']]
    assert supports_reuse(a), '先审批交付内 Pi command/stdout 配置，不自动改变成员权限'
    assert 'LOOP_PI_BIN' in a['inherit_env'], '先审批两臂继承同一个 CLI 路径变量'
out.mkdir(parents=True)
for policy, name in [('fresh','fresh.json'), ('reuse_repairs','reuse.json')]:
    plan = copy.deepcopy(rules)
    for u in plan['units']: u['developer_session'] = policy
    (out / name).write_text(json.dumps(plan, ensure_ascii=False, indent=2)+'\n')
(out / 'approved-normalized.json').write_text(json.dumps(rules, ensure_ascii=False, indent=2)+'\n')
PY

"$PY" engine/loop.py validate "$COMPARE_DIR/fresh.json"
"$PY" engine/loop.py validate "$COMPARE_DIR/reuse.json"
```

## 4. Fresh 对照启动（默认关闭复用）

仍在组合目录、同一个用户终端和上述环境中，用户亲自执行：

```bash
"$PY" engine/loop.py run "$COMPARE_DIR/fresh.json" --root "$COMPARE_DIR/fresh-data"
```

前台等待结束；启动输出给精确 RUN_ID。记录该 ID，不选 latest：

```bash
"$PY" engine/loop.py status FRESH_RUN_ID --root "$COMPARE_DIR/fresh-data" --json
"$PY" engine/loop.py audit FRESH_RUN_ID --root "$COMPARE_DIR/fresh-data"
```

结果入口：`$COMPARE_DIR/fresh-data/runs/FRESH_RUN_ID/result.md`、report.html、manifest.json。期望每次本地 Pi command 都有 `--no-session`、context.session.mode=fresh、session_path=null；不存在持久 developer 会话映射。业务成功与否按真实标准、门禁及 finalization 判断，不因为是对照就要求通过。

## 5. Reuse 可选启动

先确认 fresh 终态、原源输入未变化，且预算仍由用户认可。相同 cwd、环境、CLI 和已批准规则：

```bash
"$PY" engine/loop.py run "$COMPARE_DIR/reuse.json" --root "$COMPARE_DIR/reuse-data"
"$PY" engine/loop.py status REUSE_RUN_ID --root "$COMPARE_DIR/reuse-data" --json
"$PY" engine/loop.py audit REUSE_RUN_ID --root "$COMPARE_DIR/reuse-data"
```

结果入口：`$COMPARE_DIR/reuse-data/runs/REUSE_RUN_ID/result.md`、report.html、manifest.json。首轮新建 UUID 自有会话，用精确 `--session` 路径；只有已接受且可用的连续业务返修才共享该路径。评审/格式修复新会话；失败、缺失/坏会话或 binding 不符会明确 fresh 原因。映射 ready 只接受 JSON 布尔值，只有 true 可复用；false 仍不可复用，字符串 "false"、数字 1 等非布尔值或缺字段记录损坏映射原因并 fresh，旧会话不重绑/覆盖。v3 载荷也需有效：合法 JSON 的 message=null、缺字段/非法 content，或未支持的条目/角色/块，不猜测续接而记录 fresh 原因，旧文件不改；若选择后再损坏则适配器拒绝重绑/启动该会话。OS 能力不够应非成功停止，绝不能把这种运行列成“复用成功”。

上述公平对照使用核心前台入口，不自动加长日志简报模型。若用户选择组合入口，**两臂都**把相应 run 命令换为：

```bash
"$PY" run_loop.py "$COMPARE_DIR/fresh.json" --root "$COMPARE_DIR/fresh-data"
# fresh 终态后才启动另一臂，不在同一目录重跑覆盖。
"$PY" run_loop.py "$COMPARE_DIR/reuse.json" --root "$COMPARE_DIR/reuse-data"
```

组合入口 `runs/RUN_ID/交付结果.md` / delivery-overview.json 会独立记录额外简报（长日志且未取消时）；简报也 fresh。其费用/时间不能冒充引擎预算或复用收益。两种入口不要对同一臂都运行一遍而当成一次；新 run 保留独立编号。
