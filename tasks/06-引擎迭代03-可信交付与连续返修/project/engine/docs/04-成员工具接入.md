# 04 Pi、Codex 与自定义成员接入

## 1. 本版的真实状态

调度器通过真实子进程执行成员，不是只模拟一个“调用模型”按钮。`pi` 和 `codex` 的命令构造、角色参数、交付解析和门禁都已实现。构建环境没有安装这两个 CLI，也没有使用你的账户；因此没有真实账号端到端验证。

内置命令按 2026-10-01 查阅的官方资料实现，本地旧版本可能不支持某个标志。先查看 `pi --help`、`codex exec --help` 和版本；不要为了兼容直接去掉审批/只读/会话隔离边界。用户已有本地规范优先由拍板人审查后通过自定义适配器接入，不默认升级用户工具。

## 2. 使用本机账号，不复制密钥进规则

```bash
python3 loop.py doctor --plan examples/real_pi_codex.json --check-tools
```

doctor 不收费、不调用模型；它不证明登录有效。请通过你已经使用的各 CLI 登录流程确认可用性。凭据保存在工具原有位置或用户终端环境，程序不要求上传给网页助手。

需要通过环境变量传密钥时，只把变量名填在相应 agent.inherit_env；实际值由用户自己的终端安全设置。不要把值放 JSON、extra_args、argv 或共享日志。基础 HOME 会被保留给成员，所以成员 CLI 可读取自己的本地账户配置；这不构成账户隔离。

## 3. Pi 开发、Codex 评审的小型真实试跑

```bash
python3 loop.py validate examples/real_pi_codex.json
python3 loop.py run examples/real_pi_codex.json
```

该规则不是 TODO 模板，会在你启动后真的调用本地 Pi 和 Codex。目标仍是修复示例邀请逻辑，只有 `invites.py` 可写，测试和 baseline 受保护。最多一轮业务返修，单次成员 420 秒，总运行 1800 秒，最多 8 次成员启动。费用未精确计量。

未填写 model/provider 时使用本地 CLI 默认。正式任务建议在复制规则之后把所用型号写明确：Pi 支持 `provider`+`model`，Codex 支持 `model`；填你已经确认存在且有权限的实际字符串，不照抄未经验证的示例型号。

## 4. 内置 Codex

大致命令如下，路径由程序按本次运行生成：

```text
codex --ask-for-approval never exec --ephemeral
  --sandbox workspace-write 或 read-only
  --skip-git-repo-check --color never
  --output-schema <schema路径>
  --output-last-message <response路径>
  [--model <明确型号>] -
```

开发角色使用 workspace-write，评审角色使用 read-only。提示通过 stdin 提供，每次新会话，不 resume；最终 JSON 由 CLI 的 last-message 功能落盘。引擎不会添加不受限制的 full-access/绕过沙箱开关。

`reviewer_exec=true` 不改变内置 Codex 命令：评审仍在只读沙箱下，取证目录不可写。引擎提供目录不代表 Codex 获得了写权限；需要写脚本或输出时应在启动前选择内置 Pi 或经过审查的自定义 command 接法，不自动放宽 Codex 沙箱。此限制未用真实 Codex 账号实测。

Codex 本地配置、提供商、MCP 等可能仍由 CLI 加载。上述参数不是整个机器和网络的隔离证明；请先审查本地配置。非交互时不能要求用户在过程中批准动作，缺权限就如实失败，而不是偷偷提升权限。

## 5. 内置 Pi

```text
pi --print --no-session --no-extensions --no-skills
   --no-prompt-templates --no-themes --no-context-files --no-approve
   --tools <按角色指定>
   [--provider ...] [--model ...]
```

开发工具：read,bash,edit,write,grep,find,ls。
评审工具（默认 `reviewer_exec=false`）：read,grep,find,ls。
评审工具（单元 `reviewer_exec=true`）：read,bash,write,grep,find,ls；只增加 bash 和 write，不开放 edit。

提示从 stdin 输入，最后的 stdout 必须为单一 JSON。默认评审不开放 bash；开启取证时可执行只读的取证命令，脚本和输出只能写入指定取证目录，不得修改候选。必需门禁仍由引擎 gate 独立执行，不用评审自跑命令替代。Pi 工具运行于本机进程权限下，工具列表不等于系统沙箱。

如果本地 Pi 版本不认识 --no-context-files 等标志，通常会退出并留下错误日志。不要把它误判为业务未达标；对照 `--help` 后更新你认可的兼容命令或使用 command。

## 6. 接任意本地工具

自定义 command 示例（路径换成真实 wrapper）：

```json
{
  "kind":"command",
  "identity":"my-independent-reviewer",
  "argv":["{python}","/absolute/path/to/member_wrapper.py","--context","{context}"],
  "output":"file",
  "inherit_env":[]
}
```

程序以代码副本为 cwd、提示为 stdin 启动 argv，绝不自动经过 shell。wrapper 需阻塞等待任务完成，最后生成符合协议的 JSON 并退出。它可以调用你的既有工具，但必须显式处理新会话、权限、审批和结果规范；程序无法从一个任意命令推断这些保障。

成员收到环境变量：`LOOP_CONTEXT`、`LOOP_RESPONSE`、`LOOP_CODE`、`LOOP_ATTEMPT_ID`、`LOOP_ROLE`、`LOOP_UNIT_ID`。完整上下文包含目标、标准、权限、当前代码、必要反馈、门禁证据、JSON schema 与只读 response.template.json 路径。

单元 `reviewer_exec=true` 时，评审方还有 `scratch_path` 和同值的 `LOOP_SCRATCH`，指向已存在、可写且不在候选副本中的取证目录。脚本及输出只能写入这个目录；不得修改候选副本、门禁证据、规则、交接记录和原始项目。格式错误重交时，前一次取证内容复制到新的取证目录；业务返修后的新评审不继承旧候选证据。被接受交付引用的文件设为只读并纳入指纹核对，未引用文件留在原处，不删除。开发方与未开启开关的评审方 `scratch_path=null`，没有 `LOOP_SCRATCH`。

自定义 command 的工具权限由规则中的 argv（及其 wrapper）决定，开启开关不会使引擎改写 argv 或自动增加工具；拍板人必须自行给评审工具配置只读命令取证及取证目录写入能力。

output=file：wrapper 将一个 JSON 对象写入 LOOP_RESPONSE。output=stdout：stdout 只能输出最终 JSON，日志写 stderr。不要把多条 JSONL/进度文字混入最终输出；如果工具只提供流式事件，wrapper 负责提取最后交付，保留原始执行日志。

交付结构：

```json
{
  "attempt_id":"从context逐字复制",
  "role":"reviewer",
  "candidate_hash":"评审方复制当前候选哈希，开发方填空字符串",
  "summary":"一句话结论",
  "blocked":false,
  "criteria":[
    {"id":"S1","status":"PASS","note":"依据当前门禁和代码检查。","evidence":["gate:G1","code:invites.py"]}
  ],
  "issues":[],
  "rule_gaps":[]
}
```

实际 criteria 必须覆盖当前所有 ID。这里是一行的格式示意，不能直接用于含 S1、S2 的任务。PASS 需要证据；允许 FAIL 和 UNKNOWN；问题清单必须绑定现有 criterion_id。

证据写法：

- 默认 `evidence` 数组只接受 `code:<项目内相对路径>` 和 `gate:<门禁ID>`；代码引用须指向当前代码副本内存在的文件，门禁引用须指向引擎提供的门禁证据。
- 仅单元 `reviewer_exec=true` 的评审方还可引用 `scratch:<相对路径>`，例如 `scratch:取证/sessions.json`。路径相对于本次 `scratch_path`，只能是存在的普通文件，不接受越界、符号链接（包括中间目录链接）或目录。开发方不得写 `scratch:`，未开启开关的评审方也不得写。
- 取证目录所有普通文件（包括未引用文件及缓存）累计大小超过 `limits.max_log_bytes`，或取证引用无效，都按交付格式错误处理。证据索引记录被引用文件的 path、sha256 与候选指纹，事后改动使 `audit` 退出 5。
- 开发方不得写 `gate:` 引用：引擎在开发方交付之后才执行门禁，自己跑过的测试写在 `note` 里；评审方可以引用本次门禁证据。
- 其他路径（绝对路径、工作区路径）、网址、日志位置不放进 `evidence`，写在 `note` 里。

JSON 语法错、漏项、过期 attempt_id、旧候选哈希、证据不存在或证据写法不合法都不会被接受。格式修复按 `max_protocol_retries` 对同一单元的开发方、评审方分别累计，一方用掉不影响另一方；任一角色耗尽自己的额度后，再出现交付格式错误仍停为 BLOCKED。每次修复重启新会话，保留已写代码但冻结代码；它仍消耗总调用预算。不能靠格式修复偷偷改业务。

## 7. 禁止的适配器行为

不带着旧会话继续；不修改标准、调度状态或旧交接；不启动 detached/setsid/远端后台作业；不把“已发起请求”当成已完成；不访问生产写接口；不自己重试无幂等保证的外部副作用。

本版只保证追踪受管进程组，无法撤销已经发送到外部的动作。需要生产发布时，另行设计可靠幂等与权限边界，不把本版当发布系统。
