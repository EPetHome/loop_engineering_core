# 0.4.0 配置、工具接口与记录

本文是实现参考，不是要求普通编排模型每轮通读。日常只读Skill与工具返回；真实结构以`rules.py`、`capabilities.py`和`guard_server.py`为准。

## 1. schema v2 与v1

v1继续严格拒绝未知字段，不把新字段悄悄塞入旧格式。v2增加以下顶层字段：

| 字段 | 作用 |
|---|---|
| `execution_profiles` | 已登记的固定执行配方 |
| `security` | `strict`或显式`audit-only`；引擎缺省值仍是 strict，本项目计划按用户决定显式写 audit-only（不是操作系统隔离） |
| `operation_budgets` | 自定义操作额度，例如C06的执行次数 |

v2单元增加 `build_profiles`、`input_from`、`review_mode`，新增`kind: verify`。门禁增加`profile`和可选`budget_key`。

2026-10-03 新增（均为可选）：

| 字段 | 位置 | 作用 |
|---|---|---|
| `review_scope` | 单元，默认 `frozen` | 第 2 轮起仅失败门禁、未解决的已知必须修、改动文件的新必须修问题阻断；其余新必须修记为 `DEFERRED`，结果页列「遗留发现」。连续两轮只剩改动处新问题时「不收敛」。`open` 只取消文件冻结，不取消分级或停滞 |
| `max_selftests` | 单元 | 本单元自测总额；不写时把 `limits.max_selftests` 平均分给有构建配方的单元，再按轮累计分配 |
| `files` | 评审 issues 里的每一项 | 问题涉及的项目内相对路径；冻结单元从第 2 轮起必填 |

准备检查的 `warnings` 会列出含"全部 / 所有 / 完整 / 任何"等无边界措辞的验收标准，不阻断；启动预览会列出全部构建和检查命令，以及每个单元的返修上限和评审口径。

启动预览还按单元、角色列出成员身份、配置的模型与思考档位、配置 `--tools` 和实际受管工具。schema v2 的随包 `pi_member.py` 按角色固定工具集，`--tools` 不能扩大或缩小它；配置与实际不一致时，预览明确标出替换，适配器在 stderr 记录两份工具清单（保存在成员任务日志）。开发正常轮与业务返修使用开发工具集；格式修复与评审只读。模板已列出完整默认工具。自定义适配器或旧 schema v1 的最终工具标为“未核实”，不从名字猜测能力；缺少的模型或档位不补默认值。预览不调用模型，也不证明账户或远程服务可用。


已有limits、notes、completion、criteria和修改边界继续有效。v2规范化是幂等的；任务自己手填的门禁argv/output_paths/timeout/max_reruns若与配方不同会被拒绝，而不是静默采用另一值。

## 2. 一份构建配方

下面只是形状示例，实际项目不要不经核对就照抄模块与报告：

```json
{
  "maven-test": {
    "argv": ["mvn", "-B", "-o", "-Dmaven.repo.local={cache}", "test"],
    "cwd": ".",
    "cache_dir": "/人工选择的独立缓存目录",
    "max_cache_bytes": 2147483648,
    "max_cache_files": 200000,
    "output_paths": ["module-a/target/"],
    "evidence_paths": ["module-a/target/surefire-reports/TEST-example.xml"],
    "timeout_seconds": 600,
    "network": false,
    "inherit_env": [],
    "probe_allowed": false,
    "max_reruns": 0,
    "description": "明确本配置的工具和范围"
  }
}
```

`argv`是参数数组，不是Shell文本。支持`{python}`、`{engine}`、`{code}`、`{workspace}`，使用`{cache}`必须显式登记cache_dir。cwd是复制后源码的相对目录。output_paths是副本中新产物范围；evidence_paths是必须存在的明确文件，必须位于声明输出内。路径不使用通配符。

配方源码、调用脚本和插件本身仍可能包含副作用；固定配方并不自动等于安全代码。严格模式加写入沙箱、网络开关、时限和运行后完整性核对；未知行为应报错而不是扩大输出白名单。

缓存独立加锁。等待锁也受阶段期限限制；缓存配额单独检查。缓存可以加速依赖获取，但不会带来PASS复用。当前不自动播种缓存、不删除旧缓存、不承诺不同工具链能安全共享同一个缓存。

## 3. 单元与门禁

开发型单元引用：

```json
{
  "id": "repair",
  "kind": "work",
  "goal": "已审业务目标",
  "developer": "dev",
  "reviewer": "review",
  "review_mode": "independent",
  "writable_paths": ["src/"],
  "protected_paths": ["tests/"],
  "build_profiles": ["maven-test"],
  "criteria": [{"id":"C1","text":"已确认的完成标准","gate_ids":["G1"]}],
  "gates": [{"id":"G1","profile":"maven-test"}]
}
```

程序生成这个门禁的命令、临时输出和相关时限；不要求模型再次手填相同字段。开发自测仅能选择本单元build_profiles中的配方。

### 单元字段（v2）

| 字段 | 默认 / 校验 | 行为 |
|---|---|---|
| `review_bar` | 可选；去首尾空白后非空，≤ 600 字；必须有 reviewer | 默认口径与单元口径同时给评审，冲突以单元为准。普通开发可省略；验收脚本可明确「正确实现被误拒算必须修，检查可以更严算建议，点名核心行为除外」 |
| `first_round` | `develop` / `review`，默认 develop；verify 不得声明；review 必须有 reviewer | review 首轮仅冻结输入、跑门禁及评审，`developer=None`、程序交付 `review_first`；不通过再走正常返修 |
| `max_selftests` | 可选正整数；实际总额取与运行总额的较小值 | 是单元总数，按 `max_repairs+1` 轮累计分配，不是每轮额度 |

### 成员报告与提示词

| 字段 | 规则 |
|---|---|
| `issues[].severity` | v2 受管 reviewer 所有轮次必填 blocking / advisory；级别以首次提出为准 |
| `counterexample` / `locations` | 按台账首次级别校验：新 blocking 必须给非空反例和至少一条位置；已知 blocking 重报可省略，填写时必须非空、合法。位置格式 `相对路径:行` 或 `相对路径:起-止`，必须是当前候选普通文件及合法行号 |
| `spec_refs` | 可选字符串数组，规格条款编号 |
| `code_map` | 仅 developer 可选；去首尾空白后非空，原字符串 ≤ 8000 字。列新建、修改、删除文件的相对路径、对应标准和取舍；可用以 `/` 结尾的目录前缀统一覆盖；交接已接受的 `{round,text}`，本轮省略则清空为 null |

v1 / 非受管报告仍可省略新 issue 字段；没写 severity 按 blocking，提供时检查类型。v2 受管评审的标准判 FAIL 必须有该标准的失败门禁、仍 OPEN 的已知必须修问题或本报告的 blocking；只有建议时判 PASS。规格缺口写 `rule_gaps`，不能据此判 FAIL。ADVISORY 不阻断、不交开发、不用关项；结果页另列「建议项」。

受管评审同一报告里的同一问题（标准 ID 和描述按 `finding_id` 原样匹配，不去空白、不忽略大小写）只能出现一次，重复会拒收并要求合并。已知问题重报成另一 severity 不报错，但元数据要求和 FAIL 依据都使用台账首次级别。已接受台账的反例、位置和规格引用只由非空合法新值更新，不被空字符串或空数组覆盖。

v2 受管开发交付写了地图时，程序用单元输入到本次交付的 `changes()` 核对全部新建、修改、删除的文件（不要求目录条目）。按 POSIX 相对路径原样匹配，路径前后不能紧挨字母、数字、`_`、`-`、`.`、`/`；单独出现的以 `/` 结尾目录前缀可覆盖其下文件，不把 `a.py` 当成 `data.py` 的一部分。无文件改动时任意合法地图通过；不校验地图是否列了不存在的文件。漏写按协议错误处理，列出最多 20 条路径及剩余条数，冻结代码、仅修报告，消耗一次协议重试；重试耗尽则 BLOCKED，`max_protocol_retries` 不变。

返修开发先看地图和问题位置，再按需读文件；复审先看完整差异、地图和改动处，不从头通读。地图只更新于接受的开发交付，未写地图的接受交付会清空旧地图；先评审轮没有开发交付，所以不执行覆盖核对；其后的首次开发没有旧地图是正常的，但如果提交了新地图，仍然按 M1 核对。评审提示词只在顶层携带一份地图，`context.json` 和 `accepted.json` 保留完整开发报告。

`continue --from-round N` 选择续接单元第 N 轮候选，与 `--fresh-unit` 互斥。没评审过的候选自动先评审；已评审候选先开发。携带所选候选的问题快照，不带 RESOLVED、ADVISORY、遗留或规则缺口。只起草，仍需重新登记、准备和用户启动。

验证型单元：

```json
{
  "id": "C06",
  "kind": "verify",
  "goal": "仅验证明确候选，不修改业务代码",
  "depends_on": ["repair"],
  "input_from": "repair",
  "review_mode": "gates",
  "criteria": [{"id":"C06-pass","text":"本场已审程序验收标准","gate_ids":["C06-gate"]}],
  "gates": [{"id":"C06-gate","profile":"c06-scene","budget_key":"C06"}]
}
```

必须同时登记对应配方并设置`operation_budgets: {"C06": 1}`。`budget_key`每次该门禁实际准备执行时消耗，重跑也算。它不自动知道脚本内部偷偷执行了几场或调用了几次模型；真实场景的内部边界仍要在受管执行配方里明确。

gates模式不调用独立模型评审，只能用于用户明确采用纯程序验收的标准；结果`reviewed:false`。需要Astra判断就使用independent并声明reviewer。v2的`reviewer_exec:true`目前明确拒绝：尚未提供受管评审任意执行工具，机械检查应声明为门禁，不能静默删除原有验收要求。

有依赖的verify必须显式input_from；不能根据“最近候选”猜。最终集成verify所选输入的生产链必须覆盖所有代码生产分支，否则拒绝把独立通过拼成整体集成。

## 4. 资源默认值

v2延续v1基础限额，并分离以下维度；这些是工程默认，不是经过真实90分钟业务测试的容量保证。

| 字段 | 默认 |
|---|---:|
| `max_log_bytes` | 每个诊断流保留8 MiB前缀 |
| `max_event_bytes` | 单条事件8 MiB |
| `max_response_bytes` | 最终响应1 MiB |
| `max_evidence_bytes` | 每次证据采集32 MiB |
| `max_build_bytes` | 派生产物1 GiB |
| `max_build_files` | 派生产物100000项 |
| `max_run_bytes` | 受管运行目录组4 GiB |
| `max_run_files` | 受管运行目录组300000项 |
| `max_selftests` | 20次 |
| `max_gate_executions` | 40次 |
| `max_total_repairs` | 10次 |

### 自测与时间预算

| 项 | 规则 |
|---|---|
| 准备时限提醒 | 有 developer 且 `max_seconds < (max_repairs+1)×stage_timeout_seconds` 时不阻断提醒；预览显示 `floor(max_seconds/stage_timeout_seconds)` 轮开发容量，不代表包含门禁和评审的实际耗时 |
| 自测累计上限 | 单元总额 C、轮数 M+1，第 r 轮为 `ceil(C×min(r,M+1)/(M+1))`；20 次 / 返修 2 次是 7 / 14 / 20，未用的顺延；运行级总预算仍同时检查 |
| 每轮计时 | `history[i].timing` 有 developer_seconds、gate_seconds、review_seconds；墙钟秒数保留一位小数，包含协议/基础设施重试；没有阶段记 0 |
| 返修预留 | `reserve=ceil((gate_seconds+review_seconds)×1.25)`；剩余扣预留须大于 0，且至少为上轮开发用时的一半；首轮先评审时开发为 0，need=0 |
| 开发截止 | 返修 timeout 取阶段时限与 `deadline-reserve-now` 的较小值，不改 guardian 的运行/单元 deadline；普通阶段或空闲超时仍 BLOCKED |
| 工具回执 | loop_build / loop_submit_check / loop_delete / loop_copy 的开发回执含整数 seconds_left（最小为 0）；返修提示列扣除预留后的开发限时 |

诊断前缀可能结束在一条JSON中间，retention.json会显示不完整。不要把它重新喂给解析器证明原始事件完整；实际运行状态来自持续消费的完整事件流及封存记录。

总磁盘限制是周期检查，非操作系统磁盘配额；短时间写入可以超过上限后再被停止。目录大小扫描也有开销，大项目需要后续性能验证。源文件限额与构建产物/报告限额不再混为一个参数。

## 5. MCP接口

桥采用本地stdio JSON-RPC，工具调用转到独立准备服务的Unix socket。不提供HTTP监听、不使用OpenAI密钥、不自动启动服务。不完整或超限请求返回错误。

| 工具 | 实际参数 |
|---|---|
| `loop_prepare_begin` | `project_id` |
| `loop_prepare_patch` | `prep_id, revision, changes` |
| `loop_prepare_check` | `prep_id, revision` |
| `loop_prepare_probe` | `prep_id, revision, question_id` |
| `loop_prepare_seal` | `prep_id, revision` |
| `loop_prepare_status` | `prep_id` |
| `loop_project_info` | `project_id` |
| `loop_project_list` | `project_id, path` |
| `loop_project_read` | `project_id, path, start_line, max_lines` |

begin/info可返回完整当前规则；patch/status不反复返回全套规则。seal返回绑定摘要、检查范围、预览路径和启动命令，不包含启动工具。字段名称是revision，不是设计稿里的expected_revision。

project_read限制项目内普通文本、每文件1MiB、每次最多200行和64KiB；拒绝符号链接及常见敏感路径。这不是通用秘密扫描器。列表最多300项，超出会标记截断；当前没有大型仓库全文语义索引。

配置变化patch采用允许顶层字段的替换：title/task_id/notes/units/completion/limits/operation_budgets。source、agents、profiles、security、excludes不能由普通准备更改；允许范围不可扩大，保护路径不可移除，预算只能收紧。业务标准本身仍需人工在启动预览确认，不承诺程序自动理解每句需求。

## 6. 目录与证据

```text
STATE/
  guard.sqlite3                 项目、准备、授权、启动请求、额度预留
  locks/                        进程锁
  prepared/<prepared-id>/       冻结规则与预览
  probes/<prep-id>/...           明确授权的执行条件探测

DATA/
  .loop-managed.json            受管根标记
  runs/<run-id>/
    rules.json / manifest.json  原有权威状态，新增admission关联
    units/<unit>/attempts/...   调用上下文、成员活动、受控自测证据
    units/<unit>/gates/...      正式构建与门禁证据
    result.md / report.html     原有结果
    交付结果.md                  根包装程序摘要，默认不调用AI
  checkouts/...                 当前调用编辑区
  snapshots/...                 冻结输入与候选
```

精确层级以manifest/context给出的路径为准，不自行拼接latest或假定所有build都在同一平铺目录。构建目录里的source/home/tmp为临时数据，关键job回执和evidence进入封存与完整性核对。未提交代码只是保留现场，不能直接正式导出。

结果页的「建议项」列轮次、标准、描述和位置；「成本」按调用顺序列每会话的耗时、模型轮次、工具调用、读取/不同文件/会话内和跨会话重读、地图外读取、输入/缓存读/输出 token 及是否提供地图。地图外读取列放在跨会话重读之后，不加入运行合计。开头列运行合计；缺数据写「未知」，原成员用量 JSON 保留。读取统计来自实时事件流，不事后解析截断日志；跨会话只比较同单元。成本只展示，不设置停止上限，不代表实际账户收费。

工具生命周期不匹配、工具事件缺 `toolCallId`、开始事件缺 `toolName`、流损坏、结束时有未解析完的残留数据、解析器因事件超限抛错或工具尚未结束时，读取类统计（`reads`、`distinct_files`、`repeat_reads`、`read_paths`、`tools_by_name`）全为 null；已观察小计只存 `coverage`，例如 `reads_observed`，不冒充表格或合计数字。同单元后续会话的跨会话重读也为未知。原始日志保留上限截断不影响完整实时投影，准确数字仍显示；timeout / cancelled / 非零退出结束时，只要事件流止于完整事件、没有残留，投影也算完整，数字照常显示。

`off_map_reads` 是该会话已读取的代码目录内（`outside=false`）、不在指引范围里的不同文件数，不按读取次数累加，也不计代码目录外路径。成员调用时计算并保存 `read_guidance`：地图中的精确路径或目录前缀、`comparison.changed_from_input/changed_from_previous` 路径，以及 OPEN 且非 advisory 的 issue 的 `files` 和去行号的 `locations`。保存地图文本的覆盖规则以兼容会话中新建文件；统计随会话记录保存，`cost_sessions` 只汇总，不重解析原始日志。读取完整但上下文地图为 null 时显示「无地图」；读取未知优先显示「未知」，两者的 `off_map_reads` 均为 null，用 `off_map_status` 区分。

地图外读取只是信号，不代表违规。评审方读地图外的文件是正常行为，开发方和评审方要分开看；地图不是读权限边界，不拦截地图外读取，也不增加读取提醒或上限。

适配器专用回执采用`loop-outcome-v1`、随机nonce和有限大小的管道帧。它不是任意stderr里的JSON。管道不传给Pi及其工具子进程。外层已知取消或超时不会被晚到ok覆盖。

## 7. 错误与停止政策

| 类别 | 受管v2行为 |
|---|---|
| 配置错误/不支持能力/非法输出 | 停止，保留现场，不原样重试 |
| 诊断日志保留满 | 记录裁剪，继续解析，不视为业务失败 |
| event/response/evidence/disk硬限制 | 明确阻断，不自动放大 |
| 普通nonzero_exit/回执缺失或不匹配 | 保守阻断，不猜暂态 |
| 已明确暂态且可安全重试 | 仅白名单原因、剩余额度内重试 |
| 业务标准失败 | 开发型单元按授权返修；验证型单元不自动回开发 |
| 交付格式错误 | 原有冻结代码的格式修复路径，不等于重新开发 |
| 时间不够返修 | NOT_MET；扣除门禁/复审预留后不大于 0 或不足上轮开发的一半，不开始、不计数返修；保留当前候选和问题清单 |
| 返修开发用完本轮可用时间 | NOT_MET；只有预留截止导致的 timeout 才用此原因；没有交付，保留上一候选和问题清单 |
| 停滞 | v2 第 2 轮起，未通过且轮初 OPEN 必须修一个也没变成 RESOLVED，NOT_MET 交拍板人；不把 UNKNOWN 旧项复核、建议或遗留算入 |

当前并没有针对所有供应商HTTP错误的细致分类器，因此宁可停止，也不声称所有网络失败都能自动恢复。旧v1重试政策仍按兼容路径执行。
