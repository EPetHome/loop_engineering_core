# 项目模板：接入 Loop 的项目结构

新项目使用 Git＋隐藏受管 worktree＋项目方法＋每批一张 version:1 开发卡。不先开工、不手工同步目录；旧卡/开工/后置命令已停用，只给迁移说明。原有非 Git 项目和外部基线不自动迁移，是否改变业务流程由用户决定。

## 目录

- `项目根/AGENTS.md`、`CLAUDE.md`：原有稳定边界，本批不修改。
- `.autoreview.json.示例`：本机配置样板；替换占位符后另存 `.autoreview.json`，不跟踪真实本机配置。
- `.gitignore.示例`：本机忽略项，写入本项目 `.git/info/exclude` 或已有忽略规则。模板骨架本身随仓库交付。
- `.autoreview/methods/`：固定准备、方法自测与说明，只写一份。
- `deploy/acceptance/`：真实项目替换后的本机验收环境，localFiles 登记，不把真实测试库/凭证提交。
- `docs/requirements/`、`docs/prompt/`：需求、方案、任务与启动说明。
- `docs/batches/示例批次-20261012/批次.json`：文件名为兼容样板目录保留，内容已是新开发卡；推荐新任务叫开发卡.json。
- `docs/baseline/`：基线四页；结果链接指向同一账本/报告，不另造多个当前结论。
- `issues/`：问题单及【history】，写法只看 [README-验收标准.md「问题单」](../README-验收标准.md#问题单)，不复制第二份正文规范。
- `线上/`：业务源码位置示意，不意味着合入立刻部署。

工作区由内核按 Git 共用目录、卡、任务身份登记在隐藏空间；不再推导 `../仓库-dev分支`，旧 workspaces 配置不生成目录。已有目录不搬迁、不删除。

## 谁负责

用户拍板标准、节点与发布授权，并做业务/人工验收。协调方写提示词及卡，核对同一程序账本；开发方在各任务原会话改代码并做定向自检，程序只提交允许范围内候选。静态评审只读，测试/验收/提交/部署只按 flow 执行，不暗加旧 full 或共享预算。

## 启动与交付

1. 在有本地 dev 的 Git 项目中替换本机配置、方法和脚本占位符；`bin/loop 接入 <项目目录>` 不修改稳定规则。模板不是已验运行成品。
2. 写任务提示词及卡。单任务可不带验收，多任务必须统一验收并逐条 [责任任务]；测试命令写 tasks[].test，确实没有写“无：原因”，不是通过。
3. `bin/loop 启动 docs/batches/示例批次-20261012/批次.json --dry-run --json` 只读预览，然后同命令去掉 dry-run 启动。Pi 默认独立可输入窗口，明确后台才 --launcher background；JSON 不选后台。
4. 用 `bin/loop 查询 <卡> --json`、停止、续跑观察同一账本。各任务并行，测试/验收排本机槽；原会话返修/次数/证据不换。方法失败在开发前停止，不空跑通过。
5. 按用户实际授权沿 `bin/loop 合入 <卡>` 只合入 dev/推 origin/dev；只授权本地加 --仅本地，不补推。例外仍需真实用户决定，不伪造检查通过。不手工 merge 旧批次。
6. 卡显式提交后部署才执行部署；安全回退、未知副作用与资源分列。业务/人工验收结果另行判断，不从技术通过推定已验。

临时单会话用 `bin/loop 开发 pi|claude|codex`，只做开发评审、不自动提交或验收；直接只评审用 `bin/loop 评审 --base … --head …`，只产报告。

## 方法、来源与规则

固定方法在 `.autoreview/methods/`，参数/标准不在每批重复复制。preparation 有独立恢复预算；methods.selfCheck 按指纹自测，旧 gate 不执行。context.sources 提供原文版本导航，不取代需求/标准/授权；localFiles、链接/路径、用户索引与真实输入变化保持保护。

范围缺漏只允许真实用户确认给一个任务追加一个已跟踪普通文件，经改卡安全边界应用，保留 deny 与历史，无关任务继续。停止不是放弃，未知消费者或未保存成果不删除。问题单自动安全归档与经验批准仍用统一服务，不靠旧开工预写或队列回写。

完整写法见 [README](../README.md)、[工具清单](../工具清单.md)、[运行与维护](../项目文档/运行与维护.md)。任务/标准原文写法仍见 README-验收标准.md；历史执行方式由新卡迁移说明替代，不自动改原文。

## 内部实现：兼容入口

bin/pi-dev / bin/loop-dev 为单会话脚本，setup-acceptance.ts 为接入；pipeline.ts 只有迁移诊断，旧引擎不再内部保留。项目不需要每批拼启动脚本。

## 兼容：非 Git 项目与外部基线

原 GIT_DIR/GIT_WORK_TREE、rsync 同步和旧 dev分支资料不由本模板改写、迁移或清理。正常 Pi 单会话仍可用于非 Git 目录，仅关闭无法进行的自动评审；新卡必须使用 Git。Promate 等既有项目是否迁移须单独授权，本模板不声称它们已经迁移。
