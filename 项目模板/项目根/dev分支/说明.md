> 模板说明：开发分支 = 线上的副本 + 分支专属文件。Pi 只在这里改，loop 在这里评审、起隔离验收。这里不是 git 仓库，开工点记在外部基线。
> Promate 实例：`dev分支/`（根目录对应 `Promate产品中台/`，`promate-frontend/` 对应线上前端）；用户授权并行时还有 `dev分支2/`。

# dev分支

## 结构

- 根目录：线上代码的副本。有多个线上仓库时合成一个目录，Promate 是后端放在根目录、前端放在 `promate-frontend/`。
- 下面这些分支专属文件不合到线上，同步时也不能被线上覆盖：
  - `.autoreview.json`：loop 配置，协调方维护。
  - `deploy/acceptance/`：隔离验收环境（start.sh、reset-data.sh、GUIDE.md、种子数据），协调方准备。
  - 去掉真实密钥的配置。Promate 是 `.env` 和 `deploy/nacos/promate-auth-dev.yaml`，被线上覆盖就会连到真飞书。
  - 隔离环境需要的链接。Promate 是 `Promate产品中台/plugins -> ../plugins`。

## 外部基线

外部基线在 `~/.pi-autoreview/git-baselines/dev分支.git`，`core.worktree` 指向本目录。每批两笔提交：「开工基线」（和线上一致）、「验收环境」（协调方的配置）。启动脚本设置 GIT_DIR 和 GIT_WORK_TREE，loop 据此取 diff。

## 已知问题

- 协调方的 Claude Code 工作目录停在这里时，loop 的 Claude Code 插件会对协调会话跑评审。这时没有 GIT_DIR，取证失败，会弹「暂停（自动评审内部错误）」。
- Pi 在这里启动，会向上读到项目根的 AGENTS.md，也就是协调方的规则。
- 并行的第二个分支复制了同一套 `deploy/acceptance/`，端口和测试库会撞。
