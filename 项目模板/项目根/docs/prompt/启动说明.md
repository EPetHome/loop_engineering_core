# Pi 启动说明（<项目名>）

## 模型

- 开发：`openai-codex/gpt-6.1-sol`，`max`。
- 评审：`openai-codex/gpt-6-astra`，`xhigh`（loop 参数 `--autoreview-reviewer-model`、`--autoreview-reviewer-thinking`）。
- 自动验收：`opencode-go/deepseek-v4.1-flash`（`.autoreview.json` 里的 `acceptance.model`）。
- 写之前用 `pi --offline --list-models <关键字>` 确认型号存在；启动后核对实际加载的模型和档位。

## 工具组合

| 任务 | `--tools` | 额外 `-e` |
|---|---|---|
| 前端、插件、文档 | `read,edit,write,bash` | 无 |
| 要跑长构建、起服务 | 再加 `bg_run,bg_status,bg_logs,bg_result,bg_kill` | `pi-background-tasks` |
| 只读调研 | `read,grep,find,ls` | 无 |

权限扩展每次都加，不因为已经装了就把其他扩展全开。正常批次不用手写这些参数，`bin/pi-dev` 会固定加载；见 loop 的 `工具清单.md`。

## 开工（每批）

1. 写提示词 `docs/prompt/提示词-*.md` 和批次参数 `docs/batches/<批次>/批次.json`。批次参数只写 `name`、`branch`、`pi`、`stages`、`steps`、`scope`、`e2e` 等；不要在批次目录里写门禁、棘轮或启动脚本。
2. 确认 `.autoreview.json` 已从 `.autoreview.json.示例` 复制并替换全部 `<占位符>`；把 `.gitignore.示例` 的内容复制到项目的 `.git/info/exclude`，让 `localFiles` 里的本机验收文件不进仓库。项目固定方法在 `.autoreview/methods/`，`methods.paths` 指向它。首次或改了方法后，`loop 开工` 会执行一次方法自测和基线门禁；指纹没变就跳过。
3. 在运行版（发布分支）执行：

   ```bash
   bin/loop 开工 docs/batches/<批次>/批次.json
   ```

   它检查运行版停在发布分支（不要求干净），把本批的 `批次.json`、提示词和验收标准搬进批次分支并提交；运行版里无关的未提交改动原样保留。然后在默认开发空间 `../<仓库目录名>-dev分支` 建/切批次分支，检查并复制 `localFiles`。开发空间必须是干净的（未跟踪文件也算），不能放在运行版目录里。

4. 启动：

   ```bash
   bin/loop 启动 docs/batches/<批次>/批次.json
   ```

   单段直接开会话；多段交给流水线。写 `prompt` 的段统一经过 `bin/pi-dev`，不需要启动脚本。批次文件用开工输出里的开发空间路径（开工后提示词和批次文档已搬到那里）。

5. 运行中查状态：用开工输出里的 `状态` 命令（开发空间里的批次文件路径）。完成后由用户授权执行开工输出里的 `合入` 命令；只本地合并，不推送。

不再执行每批的同步、开工基线提交或批次启动脚本。非 git 项目的兼容做法见 `项目模板/README.md` 和 `dev分支说明.md`。
