# Pi 启动说明（<项目名>）

## 模型

- 开发：`openai-codex/gpt-6.1-sol`，`max`。
- 评审：`openai-codex/gpt-6-astra`，`xhigh`（loop 参数 `--autoreview-reviewer-model`、`--autoreview-reviewer-thinking`）。
- 自动验收：`opencode-go/deepseek-v4.1-flash`（`.autoreview.json` 里的 `acceptance.model`）。
- 写之前用 `pi --offline --list-models <关键字>` 确认型号存在；启动后核对实际加载的模型和档位。

## 工具组合

| 任务 | `--tools` | 额外 `-e` |
|---|---|---|
| 前端、插件、文档 | `read,edit,write,bash` | 无 |
| 要跑长构建、起服务 | 再加 `bg_run,bg_status,bg_logs,bg_result,bg_kill` | `pi-background-tasks` |
| 只读调研 | `read,grep,find,ls` | 无 |

权限扩展每次都加，不因为已经装了就把其他扩展全开。

## 开工（每批）

1. 把线上同步到 dev分支。用 bash 跑（zsh 的数组写法不同，排除会失效），先加 `-n -i` 演练一遍：

   ```bash
   EX=(--exclude=.git --exclude=.env --exclude=node_modules --exclude=target --exclude=logs \
       --exclude=/.autoreview.json --exclude=/deploy/acceptance --exclude=<去掉密钥的配置>)
   rsync -a -c --delete "${EX[@]}" <线上>/ <dev分支>/
   ```

   排除清单就是安全边界：分支专属文件一旦被线上覆盖，验收环境就会连到真实服务。

2. 在外部基线提交「开工基线」。第一次使用先建库：

   ```bash
   G=~/.pi-autoreview/git-baselines/dev分支.git
   [ -d "$G" ] || { git --git-dir="$G" init -q && git --git-dir="$G" config core.worktree <dev分支>; \
                    printf 'node_modules/\ntarget/\n.pi/\nlogs/\ndist/\n' > "$G/info/exclude"; }
   git --git-dir="$G" --work-tree=<dev分支> add -A
   git --git-dir="$G" --work-tree=<dev分支> commit -qm "开工基线：<批次>"
   ```

3. 放好 `.autoreview.json`，准备验收环境（`deploy/acceptance/`），在外部基线再单独提交一笔「<批次> 验收环境」，免得开发方的 diff 里混进这些文件。

4. （建议）在开工基线上空跑一次门禁：`bash docs/batches/<批次>/<批次>-工具.sh check`。结果应该是通过，或者只剩已知失败。不通过就先修门禁工具，再给用户启动命令。

5. 在聊天里把启动命令给用户：`bash <项目根>/docs/batches/<批次>/<批次>-启动Pi.sh`。
